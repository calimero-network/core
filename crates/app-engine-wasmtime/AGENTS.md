# calimero-app-engine-wasmtime - the wasmtime engine for `calimero:app`

## Package Identity

- **Crate**: `calimero-app-engine-wasmtime` (`publish = false`, prototype); wasmtime 50 (features: component-model, cranelift, parallel-compilation, pooling-allocator, runtime, std), wasmtime-wasi 50, ring (artifact MAC), subtle (its compare); no wasmtime-wasi-http
- **Entry**: `src/lib.rs` (`WasmtimeEngine`, store data, limiter, import check); `bindings.rs` (`bindgen!` over `../app-wit/wit`, calimero interfaces onto `HostCore`; the `files` `writer` and `reader` resources carry the host core's handle ids as their rep, like the cursor, and dropping one closes it), `wasi.rs` (WASI wiring), `cache.rs` (checked disk cache), `errors.rs` (trap classification)
- **Spec**: `docs/specs/app-runtime-v0.14.md` sections 4-5, D8, D19, D43, D44, S1, S2, S6, S8

## What This Crate Does

Implements `calimero_app_host::Engine`. One `wasmtime::Engine` (fuel, epoch interruption with a 10 ms ticker thread, 200 KiB wasm stack, a pinned feature set with threads, multi-memory, memory64, GC, exceptions, tail calls, relaxed SIMD and component-model async off, pooling allocator with 64 MiB slots) serves every app. `prepare` refuses imports outside the lists, reads the ABI, refuses more than `MAX_MEMORIES` defined memories, compiles through the cache, links the per-component `wasi:http` stubs and builds an `AppPre`. `invoke` runs `handle` in a fresh store per call and returns `HostCore::finish(..)`.

## Contract

- Imports: exactly `allowed_imports() ∪ stubbed_imports()`, plus any listed `wasi:*` interface at an older `0.2.z` patch (z ≤ 12; Rust std imports the stubs at 0.2.9) and any listed `calimero:app/*` interface at an older `0.5.z` patch (z ≤ 1), so an app built against 0.5.0 keeps installing and running (wasmtime links by semver within the minor). `wasi:sockets/*`, `wasi:random/insecure*` and everything else: `ForbiddenImport`. Then `NoAbi` / ABI errors.
- Per call: fuel = `budget.fuel`; epoch deadline = `ceil(budget.wall_clock / 10 ms)` ticks; memory = `min(budget.memory_pages, 1,024)` pages; 100,000 table elements; 20 core instances (a wasip2 component holds several), `MAX_MEMORIES` = 1 memory and `MAX_TABLES` = 2 tables (measured: Rust wasip2 and componentize-js 0.23 guests each define 1 memory and 2 tables), `MAX_RESOURCES` = 4,096 host resources in the store's `ResourceTable`.
- Status mapping: `Err(app-error)` → `AppError`; `Trap::OutOfFuel` → `OutOfFuel`; `Trap::Interrupt` → `Timeout` (detail `WALL_CLOCK_EXCEEDED`, `"wall clock exceeded"`); refused memory/table growth (the limiter traps instead of failing `memory.grow`) → `OutOfMemory`; `Trap::StackOverflow` → `StackOverflow`; `HostDenied` or a full resource table → `HostDenied`; an exhausted instance pool, an OS allocation failure while instantiating, or a `memory.grow` the OS refused after the limiter allowed it (`memory_grow_failed`) → `Unavailable` (`"instance pool exhausted"` / `"instance allocation failed"` / `"memory allocation failed"`: node load, not logged, retryable; D23, D36); the interrupt flag → `Cancelled` (`CANCELLED`); an instance, memory or table count over the limit at instantiation → `OutOfMemory`; `exit`, any other trap, a host panic (caught with `catch_unwind`) → `Fault`. Trap details are fixed texts or trap codes, never guest data (S10).
- WASI: wall clock = `HostCore::wall_ms`, monotonic = `HostCore::monotonic_ns`, both fixed; `subscribe-*` pollables are ready at once, so a guest sleep never blocks a node thread. `random` = the host core's RNG, a `get-random-bytes` request over `MAX_RANDOM_BYTES_PER_CALL` (1 MiB) refused with `HostDenied` before anything is allocated (the SDK asks in pieces of that size; the constant lives in `calimero-app-wit`). A guest that asks for more in one call, such as getrandom 0.2 through the preview-1 adapter, traps `HostDenied`. stdout/stderr lines → `HostCore::log` (buffer capped just over `MAX_LOG_BYTES`; a full log drops bytes, never fails the guest). Environment, args, cwd, stdin empty; no terminals; no preopens, so no file descriptor exists; `exit` traps. `wasi:http/types` and `wasi:http/outgoing-handler`: every function the component imports is a per-component stub that traps `HostDenied`, every resource an opaque host type nothing constructs (Ruling 20); wasmtime-wasi-http is not linked, because its undrained body streams block a node thread past the epoch deadline. Real `http/types` will be linked only into action stores when actions land. Nothing reaches the OS.
- Cache (S8, Ruling 38): `<sha256(component)>-wasmtime50-<config hash>.cwasm` plus `.cwasm.mac`, HMAC-SHA256 under the `cache_key` given to `WasmtimeEngine::new` over the artifact's file name and bytes. The artifact is read into memory, its MAC verified (constant-time compare, `subtle`) and only those bytes are deserialized; mismatch or error recompiles and rewrites both (temp file + rename). A party that can write the cache dir but lacks the key can neither forge an artifact nor move a valid one under another component's name; the caller derives `cache_key` from the node's storage key (node: HMAC(K_r, "calimero.components.v1")). Tests: `tampered_cache_is_recompiled`, `an_artifact_rewritten_with_its_check_file_is_not_loaded`, `artifacts_are_only_loaded_under_the_key_they_were_written_with`.

- Timer ticks: for an invocation with `timer: Some(tick)` the guest's `args` are `{"scheduled":"<ms>","previous":"<ms>"|null}` (decimal strings, D20), built from `Invocation::timer`; the invocation's own `args` are ignored. The SDK's generated `handle` reads them into `env::timer()` (the world has no timer import).

- Compute engine: `WasmtimeEngine::for_compute()` (job nodes only) uses on-demand allocation instead of pool slots, `cranelift_nan_canonicalization(true)`, memory up to 65,536 pages (4 GiB), and no disk cache (prepared components live in memory; a job node holds no key to authenticate a cache). `invoke_cancellable(app, host, budget, cancel)` replaces the epoch deadline with a callback run every tick: `cancel` set ends the run `Trap(Cancelled, CANCELLED)` (`"cancelled"`), the wall budget passing ends it `Trap(Timeout, WALL_CLOCK_EXCEEDED)`. The limiter records the peak memory it granted in `Usage.peak_memory` (every engine). The `compute` WIT interface maps onto `HostCore::compute_*`.

- Stack depth: the wasm stack limit counts native stack, whose frames differ between CPUs, so a run at the recursion limit may end `StackOverflow` on one job node and finish on another. Accepted: only a run that hits the limit can differ.

## Tests

The `testing` feature exposes `WasmtimeEngine::with_pool_size` so a test can exhaust the pool.

`tests/guests/legacy_050` is built against its own copy of the 0.5.0 `types` and `storage` interfaces (`wit/`), so it imports exactly what an app built before 0.5.1 imports; `tests/guests/files` writes, reads back and hashes a file. `tests/engine.rs` builds the standalone guests under `tests/guests/*` (each its own `[workspace]`, built with `calimero_app_build::build_component` into one shared target dir under `CARGO_TARGET_TMPDIR`). Every manual ABI includes `"abiVersion": 1`.
