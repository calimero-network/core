# calimero-sdk - the Rust app SDK runtime

## Package Identity

- **Crate**: `calimero-sdk` (`publish = false`, prototype); builds for the host (tests) and `wasm32-wasip2` (apps)
- **Entry**: `src/lib.rs` (+ `prelude`); `abi.rs` (`AbiType`, `TypeDef`, the ABI's `types` assembled at compile time), `action.rs` (`ActionCtx`, `Request`, `Response`), `blob.rs` (`BlobRef`, `BlobInfo`), `search.rs` (`SearchOpts`, `SearchMode`, `Found`, `SearchResults`), `app.rs` (the `app` attributes from `calimero-sdk-macros`, `AppState`, `AppEvent`, `bail!`), `private.rs` (`__private`: the generated `handle`, argument decoding, the ABI assembly; not an API), `encoding/{key,value}.rs`, `store.rs` (+ `store/{mem,host}.rs`), `table.rs`, `commons.rs` (paged reads, counts, clears, checked keys shared by tables and collections), `collections.rs` (+ `collections/{map,slots,list,counter,cell,set,vector,frozen,per_user,text,rich_text}.rs`, the `Nestable` trait), `env.rs` (+ `env/{wasm,mock}.rs`), `files.rs` (+ `files/{wasm,mock}.rs`), `compute.rs`, `guards.rs`, `error.rs`, `json.rs`, `bindings.rs` (wasm32 only; world `app`, or world `compute` under `--cfg calimero_compute`), `testing/{mod,directory,scenario}.rs` (feature `testing`, host only), `testing/release.rs` (feature `releases`)
- **Spec**: `docs/specs/app-runtime-v0.14.md` section 7, the SDK reference, D9, D10, D20, D47, D48, D50, D52

## What This Crate Does

The shared storage encoding (order-preserving tuple keys, deterministic CBOR values), the `Store` trait over the host's ordered key-value storage, tables with indexes, unique constraints and counts, the collections, `env` and the member/admin guards. It re-exports the `app` attributes and `#[derive(Record)]` (see `crates/sdk-macros/AGENTS.md`); apps write `use calimero_sdk::prelude::*;`. The `testing` feature adds the test harness (host target only).

## Collections

One leader applies every write in log order, so these are plain data structures, not CRDTs (v1's merge semantics have nothing to merge). Every one implements `app::StateField`, so `#[app::state]` lists it in the ABI. Multi-row reads are pages (`FindOpts` in, `Page` out, at most 1,000 rows, `limit + 1` entries read), and each paged type also iterates (`table::Iter`, re-exported at the crate root and not in the prelude: `iter`, `iter_with(opts)`, `prefix_iter`, `starts_with_iter` (`starts_with`'s string prefix, `from`/`to` ignored); `Table::{iter, scan_iter, find_iter}`; `Table::len`/`is_empty` read the table's length, kept with one `Store::add` per insert or removal of a record (once per `retain`/`remove_by`/`clear_some` call), never by an update or a refused write; a table with no length row (stored before it was kept, or emptied by `clear`) is counted through a cursor until its first insert or removal writes the row, and a write reads the `"l"` mark, never the length, so it adds no read-write conflict (D47; pinned by `tests/len.rs`, costs included); `Table::clear` removes every record with its index, unique and count entries; `Table::retain` reads each record once and removes rejected ones from what it read; `Table::remove_by(index, prefix, max)` and `clear_some(max)` on `Table`/`UnorderedMap`/`Set`/`Vector` (from the end) remove at most `max` and answer `table::Progress { removed, done }`, so a clear larger than a run's 10,000 writes is done a slice per run; pinned by `tests/bulk.rs`), which reads through one host cursor (`commons::iter_entries`: one open, then one call per batch of `limit`, 1,000 unset, only when the loop reaches it, no entry read twice) and yields a failed read once as `Err`; batch writes (`extend`, `retain`, `truncate`, `Vector::insert/remove`) take one `add` for the length, never one per element, and shifts read the tail through a cursor, not a get per element (pinned by `tests/iter.rs` `costs`, with `MemStore::calls`; `MemStore::{written_bytes, read_bytes, reset_costs}` count bytes as the host charges them); lengths are stored counts kept with `Store::add`, never a scan; `clear` deletes a batch of at most 1,000 per cursor read until none is left.

`Text` stays a sequence CRDT (Tree-Fugue, after v1's `crates/storage/src/collections/fugue.rs`) because editors send edits typed against a stale view: every character has a stable id, an insert names the id it follows and a delete names ids, so edits land where meant and concurrent runs do not interleave. Applied one at a time, a Fugue insert lands right after the character it names (tombstones included), so the text is stored as a sequence of runs (consecutive ids) in a counted B+ tree (`collections/text/runs.rs`): an edit or `id_at`/`index_of` reads and writes one run, its leaf and the leaf's ancestors (O(log runs) host calls, about 10 to 15, and a few hundred bytes), a 10,000-character paste is five runs (about 15 writes), a delete is a write per run it touches, and `read`/`chars` read every run and node once (bytes about the live text plus some 45 per run); `len` is one read. An edit that would pass a run's limits (`MAX_RUN_WRITES`, `MAX_RUN_BYTES` in `store.rs`) is `StorageError::EditTooLarge` before any write. Pinned by `tests/text.rs` `costs` (with `MemStore::{calls, writes, written_bytes, read_bytes}`) and a reference-model test in `text.rs`. RGA is not carried over (Fugue supersedes it), nor v1's `RichDocument`, undo, deltas or mark schemas.

## The generated `handle` (`__private::handle`)

- Method lookup by ABI (camelCase) name; unknown → `AppError UnknownMethod`.
- Kind: a view may run as a call (or xcall delivery); a call, timer or init method run as a view → `NotAView`; an action or a compute method runs only as `kind = action` (a compute method for any caller, the node vetted it at start); any other mismatch, and `migrate` (not in this version) → `WrongKind`.
- Callers (D13), checked after the kind, except for `init` (runs as the owner): `System` needs `allow(system)` and `App(id)` needs `allow(app = id)` or `allow(app = "*")`, else `Forbidden`; `Public` needs `public`, else `LoginRequired`. The host's checks come first (Rulings 32, 35): on a node, and in the harness, an anonymous caller reaches the guest only for a `public` method of an instance that admits one (no access grant does), otherwise the platform answers `401 UNAUTHENTICATED` before `handle` runs, so the guest-side `LoginRequired` is a backstop clients do not normally see.
- Args: a JSON object keyed by camelCase parameter names, empty args = `{}`, unknown keys refused; `u64`/`i64` (and `Option`) params are canonical decimal strings (no `+`, no leading zeros, no `-0`) and `Vec<u8>` (and `Option`) params base64url without padding (D20); anything malformed → `BadArgs` (`{"message": .., "param": ..}`; `param`, the failing parameter dotted into records, only when one is at fault; tests in `private.rs`).
- Timers: `#[app::every]` implies `allow(system)` (Ruling 26), so the ABI says `allowSystem: true` on every timer.
- Timer ticks: for `kind = timer` the engine passes the tick as `args`, `{"scheduled":"<ms>","previous":"<ms>"|null}`; `handle` sets `env::timer()` from it (and clears it for every other kind).
- Results: JSON; a `u64`/`i64` (or `Option`) result is a decimal string, a `Vec<u8>` (or `Option`) result base64url; `()` and `init` give `null`. Records inside results: their `u64`/`i64` fields are decimal strings and `Vec<u8>` fields base64url too (`json::*_auto`).

## D20 conversion rule (Ruling 27)

The macros convert exactly these types, at the top level of a parameter, a result, a record field, or an event or error field: `u64`, `i64`, `Vec<u8>` and `Option` of each. The same types nested inside another type the macro can see (`Vec<u64>`, `Option<Vec<i64>>`, `Option<Option<u64>>`, tuples, arrays, maps, `Vec<Vec<u8>>`) are a compile error naming D20 ("u64 inside Vec<u64> would lose precision in JSON (D20); wrap it in a Record or use a string"). Limit: the macro sees only the tokens it is given. A user struct with plain serde, or a `type` alias, is opaque to it, so a `u64` inside one still reaches JSON as a number; use a `Record` (its derive converts the fields) or a string. `#[derive(AbiType)]` on such a struct refuses those fields unless they say their JSON: a D20 `with`, or `#[abi(plain)]`, which keeps the number (or array of byte numbers) and describes it as `u64_number`/`i64_number`/`byte_list` (`crates/sdk-macros/AGENTS.md`).
- Errors: the wire `app-error` is `{ code, message }` with `message` = the fields as JSON (`{}` when none), e.g. `Taken` / `{"start":"7"}`.

## Rules

- Key layouts are the cross-language contract (the TypeScript SDK must produce the same bytes): change them only with the spec.
- Table counts, `Counter::add` and every collection length use `Store::add`, never read-modify-write (D47).
- Keys over 1 KiB are refused with `StorageError::KeyTooLong` before any store call (D50).
- Run limits (C10): `Store::put`, `delete` and `add` return `Result`; on the guest they call WIT `storage.put-checked`, `delete-checked`, `add-checked` (0.5.7), so the write past a run's 10,000 writes or 1 MiB is `StorageError::RunLimit { limit, max, attempted }` (`error::RunLimit::{Writes, Bytes}`), not a trap, and writes nothing. As an `AppError` it is the typed `RunLimit` with fields `limit` (`"writes"`, `"bytes"`), `max` and `attempted` as decimal strings; `env::emit`, `env::xcall` and `env::start_action` answer the same `RunLimit` for the host's run-bytes soft error (`AppError::host_soft`). Every node gives the same answer for the same run. A method that answers `Ok` after one keeps the writes made before it, so pass it on with `?`. `MemStore` counts no runs and refuses nothing.
- Queries read `limit + 1` entries through the cursor and no more.
- `bindings.rs` declares the `handle` export but never exports it: the code `#[app::logic]` generates does, through `__private::bindings::__calimero_export_handle!` and `__private::Export<State>`.
- `--cfg calimero_compute` (set by `calimero-app-build` for the compute component) binds world `compute` and exports `run` through `__calimero_export_run!`; the host calls that world lacks (`env/wasm/denied.rs`, `store/host_denied.rs`) trap, and are dead code unless a compute method reaches them, so the linker drops the imports. `compute::run_id`, `inputs` and `progress` reach `job` only under the cfg; elsewhere there is no run. `compute::start` and `cancel` reach `runs` only without the cfg; in the compute build they trap, as the other calls the compute world lacks.
- `#[app::error]` and `#[app::event]` must live in the `#[app::logic]` module (their ABI constants are picked up there; elsewhere the ABI lists none), and one module takes one of each: a second `#[app::error]` enum in a module is refused (`__CALIMERO_ABI_ERRORS` defined twice, pinned by `tests/ui/second_error.rs`).
- Actions (D12, D17, D27): `ActionCtx::{key, view, call, fetch}` over the WIT `action` interface and `wasi:http` (`fetch` writes the body and finishes it before `handle`, then reads the response whole; `Request::get/post/header`, `Response::json/text`); errors are `ActionView`, `ActionCall`, `Fetch`. `env::start_action(method, &args)` (calls and timers) returns the action's key; a refusal is `StartAction`. On the host target (`env::mock`) actions answer an error: they run only in a component.
- `env::xcall(app, method, &args)` (D25) sends JSON args through the WIT `xcall.send`; a host soft error is `AppError` `Xcall { message }`.
- `env::via()` (WIT `context.via`, 0.5.2): for a call another app made as the person it serves, with that person's grant (`caller()` is the person), the app it came through; `None` otherwise and on the host target's mock unless `MockState::via` is set.
- `env::linked(name)` (WIT `context.linked`, 0.5.3): the app linked under a name of the release's `uses`, read at any time; `MockState::links` on the host target's mock, `Org::link(name, app)` and `TestApp::link(name, Some(app) | None)` in the harness.
- `env::grant_scope()` (WIT `context.grant-scope`, 0.5.6): the scope (JSON text) of the caller's grant on the instance, set by its managers on the person's grant or the invite that made it; `None` for anyone else. The platform admits, the app scopes. `testing::Org::scope(account, json)` sets it for `TestApp`.
- `env::Caller::Visitor { link, key }` (WIT `context.visitor`, 0.5.6): an anonymous visitor through one of the instance's public links; `env::caller()` asks `context.visitor` when the WIT caller is `public`. Only `#[app::public]` methods admit it (`private.rs`), and `guards` and `PerUser` refuse it with `LoginRequired`. The harness has `TestApp::visitor(link, key)`, which the node's `403` for a method that is not public mirrors.
- `env::unit_of()` (WIT `context.unit-of`, 0.5.5): the app id of the instance whose unit this app is a member of (the one whose release created it with `uses`, `mode = "create"`), `None` otherwise and in a compute run; the node derives it from the system state (the app whose `links` hold this one). Confidential KV and Private Inference releases take `app:<env::unit_of()>` as their admin, so the instance that created them uses them with no grant step. `MockState::unit_of` on the mock, `Org::unit_of(app)` in the harness.
- `env::fetch(&Request)` (D76): outbound HTTP from a call, timer or delivery over `wasi:http`, as `ActionCtx::fetch`; a failure is `AppError` `Fetch { message }`. The harness answers it with `t.mock_http` in every run.
- `env::xcall_call::<T>(app, method, &args)` and `env::xcall_view::<T>(..)` are futures (`xcall::Pending<Result<T>>`, args serialized at once, `BadArgs` if they do not): the target's JSON result decoded as `T` (`BadOutput` otherwise); a failure is `AppError` `XcallFailed` whose fields are the failure's JSON object (the target's `{code, fields}`, or `{message}`). They are awaited in an `async fn` app method: `#[app::logic]` runs every `async fn` (call, view, timer, action, init; not a compute method) with `xcall::block_on`, a single-threaded executor (`xcall.rs`) that polls the method until it waits only on xcalls, sends the ones queued since the last round as one `env::xcall_batch` (WIT `xcall.batch`, 0.5.4) in poll order, stores the answers and polls again; a method pending on anything else panics (traps) rather than looping, and an xcall future polled outside the executor panics. `app::join!` (2 to 8 futures, awaited, answered as a tuple; `__app_join`, `xcall::Join2..Join8`) and `app::join_all` poll every future each round, so their xcalls go in one batch; awaits in sequence make a batch each. A dropped future's request is left out of the batch. The SDK no longer calls WIT `xcall.call`/`view`. On the host target (`env::mock`) `MockState::sync_xcalls` answers them (else an error) and `sync_batches` records each batch; tests in `xcall.rs`.
- Typed clients for the apps a release `uses` are generated, not written: the app's `build.rs` is `calimero_app_build::uses::build()` and its code brings `$OUT_DIR/uses.rs` in with `app::uses!()` (`__app_uses`) (`uses::<name>()`, `uses::<name>::{Client, Error, ..}`), built from `calimero.lock` and `calimero/abi/<name>.json` (`meroctl app uses update`). The client's call and view methods answer `xcall::Pending<Result<T, Error>>` futures (`xcall::Pending::call`/`view` with a `decode` closure over `xcall::decode`); it is a layer over `env::linked`, `xcall::Pending` and `env::xcall` and reaches serde through `__private::{serde, serde_json}`, so those re-exports are part of what generated code relies on; a target's error decodes from `XcallFailed { code, fields }` and goes back out in the same shape. Raw `env::xcall*` stays the way to call a target not known at build time. A call commits in the target's log and is not rolled back if the run fails afterwards. Generator: `calimero_app_abi::codegen::rust`; examples: `apps/planner`, `apps/booking`.
- `env::emit(event, audience)` takes an `#[app::event]` value (spec); `env::emit_raw(name, data, audience)` takes any serde value.
- `env::mock` (host target) is the stand-in for the host in tests.
- `compute`: `run_id() -> Option<String>`, `inputs() -> Vec<BlobRef>` and `progress(percent, step)` for `#[app::compute]` methods (`app::compute`, `app::compute_result`); on the host target there is no run, no input, and progress is dropped. A compute run's output files are sealed blobs like any file: `finish` returns a `BlobRef`, and the run's outputs are retained (R8) only if its `#[app::compute_result]` method stores their `BlobRef`s; the node passes that method one typed outcome, not the compute method's bare return value; a result method that does not store them lets them be collected. `start(method, &args, &[BlobRef]) -> Result<RunId>` (args as JSON, `null` sends none) and `cancel(&RunId)` are for logged writes (call, timer, init, xcall delivery); a refusal is the `Compute` error with the host's message (see `calimero-app-host` `runs`), and on the host target both fail with `compute runs need a node`.
  An input must be one of the app's own sealed files, named once.
  A run's inputs are held until it ends, even if no state refers to them.
  `ComputeOutcome` (`compute.rs`) is that outcome: `run`, `method`, `attempt`, `status` (`done`, `failed` or `cancelled`), `reason`, `result` (the return bytes as base64, only when done), `outputs` and `usage`.
  Each of `outputs` is a `ComputeOutput { id: BlobRef, size, sha256 }`, the size and SHA-256 being the plaintext's, and its `id` is what the result method stores to keep the file.
  The result method takes the whole outcome as its one parameter, whatever the parameter is named (`calimero-sdk-macros` decodes the object, not an `{ "outcome": .. }` wrapper).
  Sizes and fuel are decimal strings in the JSON (Ruling 27), and the usage fields are camelCase.
- `compute::publish(&BlobRef) -> Result<BlobRef>` turns the output of one of the app's done compute runs into a plain blob (the SHA-256 of the plaintext), for logged writes only; store the answer to keep it, and `BlobRef::grant` gives a link.
  Anything else answers the `Compute` error with message `NOT_A_RUN_OUTPUT`; on the host target nothing is an output, and `TestApp::add_run_output` seeds one.
  The decision of who may publish is the app's, in the method that calls it.
- `files`: `create() -> Writer` (`std::io::Write`, `finish() -> BlobRef`, dropped unfinished leaves no file), `open(&BlobRef) -> Reader` (`std::io::Read`; an empty buffer reads nothing; the host refuses it outside a compute run), `info`; a file is a sealed blob, so store the returned `BlobRef` in state and drop it to delete (no `delete`); errors are `AppError` code `Files` with a `message` field; `From<std::io::Error>` gives `Files` for the Reader's and Writer's own errors and the neutral code `Io` for any other io error. On the host target a thread-local in-memory store stands in (a finished file takes effect at once, and it has none of the host's soft errors; only `TestApp` shows the host's commit semantics, because they need the host core); the harness gives the real component a `MemoryFiles` provider and applies a committed call's new files, with `TestApp::add_file` and `TestApp::file` to seed and inspect (it does not collect unreferenced files).

## Encoding contract (the TypeScript SDK must match)

- **Keys**: tag byte per part (none 0x00, bool 0x10, int 0x20, string 0x30, bytes 0x40); ints are sign-flipped big-endian 16 bytes; strings and bytes escape `0x00` as `0x00 0xFF` and end with `0x00 0x00`.
- **Collection keys**: every key starts with the collection's name (the state field in camelCase) as a string part, then a kind part: `UnorderedMap` `(name, "m", key..)`, `Set` `(name, "s", element..)` holding CBOR `null`, `Vector` `(name, "e", position)`, `Cell` `(name, "v")`, `Frozen` `(name, "f", hash as 32 bytes)`, `PerUser` `(name, "u", account)`, `Counter` `(name, "n")`, `List` `(name, "o", position)` holding `{id, value}` and `(name, "i", id)` holding the position as a CBOR byte string (a position is 8 big-endian bytes of a counter starting at 2^63, then a fraction with no trailing zero byte: appends step the counter, an insert between takes a fraction between its neighbours'); the map, set, vector and list keep their length at `(name, "n")`. A collection's keys start at its `KeyPath` (`commons.rs`): a state field's is `(name)`, so the keys above are unchanged; a collection that is a map's value under key `k` starts at the map's path, then `"c"` and `k`'s encoded tuple as one bytes part, `(name, "c", encode(k))`, and adds its own kind and parts after it (`(name, "c", encode(k), "e", position)` for a nested `Vector`), level by level. `Text`: a run of characters with consecutive ids at `(name, "r", start)` as `{text, dead}` (`text` the live characters, `dead` the deleted offsets as sorted, disjoint, non-adjacent `[from, to)` pairs; at most 2,048 characters, id = start + offset; a run is split only where an insert lands inside it, the tail becoming `(name, "r", start + offset)`); the counted B+ tree that orders the runs, its root at `(name, "h")` and every other node at `(name, "x", id)` as `{leaf, parent, items}` (`items` in document order as `[key, live]` pairs, `key` a run's start in a leaf or a child's id above, `live` the live characters under it; at most 64 items; `parent` the parent's id, null under the root; node ids come from `(name, "i")`); `(name, "l", start)` the leaf holding a run (a node id, null for the root); the live length at `(name, "n")` and the next id at `(name, "i")`. `RichText` adds marks at `(name, "k", id)` as `{key, value, start, end, endInclusive}`, ids from the same `(name, "i")`.
- **Table keys** (`table.rs`): under the table's `KeyPath`, the record at `(table, "r", key..)`, an index entry at `(table, "i", index, fields.., key..)` and a unique entry at `(table, "u", name, fields..)`, both holding the record's storage key, a count at `(table, "c", name, fields..)`, the length at `(table, "n")` (written once by counting the records, then only added to) and its mark at `(table, "l")` holding CBOR `null`. A missing length is never started from 0 under records it did not count. `(.., "l")` and a zero `(.., "n")` are bookkeeping for a map of collections (`slots::is_bookkeeping`).
- **Key length (D50, ruling 24)**: the host refuses keys over 1,024 bytes. The SDK caps every key it stores (record, index, unique, count, map, counter) at 1,023 (`MAX_SDK_KEY_BYTES`), so derived bounds (`last ++ 0x00`, `prefix ++ 0xFF`) always fit. Every range bound and decoded cursor is checked before any store call: bounds give `KeyTooLong`, a cursor gives `BadCursor`.
- **Unique constraints use SQL NULL semantics (ruling 23)**: when any field of a unique constraint is `None`, no unique entry is written or checked (insert, upsert, update, remove). Two records with no email both insert; the same `Some(email)` still clashes.
- **Values**: deterministic CBOR (RFC 8949 core). Field names are camelCase (applied by the `#[app::state]`/record macro, not by the SDK). `None` is written as CBOR null, never omitted. An integral float stays a float (`1.0` is `f93c00`), floats use the shortest exact form, `-0.0` is preserved, NaN is refused, map keys sort by encoded bytes, lengths are definite.
- **Bytes as a value**: `json::Bytes` (re-exported as `calimero_sdk::Bytes`) is a CBOR byte string when stored and base64url in JSON (`bytes_auto`); a bare `Vec<u8>` in a collection value or plain struct is a CBOR list of numbers, about twice its size.
- **Files**: `files::Writer` gathers small writes and sends them `WRITE_BUFFER` (64 KiB) at a time, a large write as it is; a refused write surfaces on the `write`/`flush` that sends it or on `finish`.
- **Table updates**: `update`/`upsert` neither re-check nor re-write a unique entry the record already holds; `UnorderedMap::update`/`get_or_insert_with` read the key once; `first`/`last` read one entry.
- **JSON (D20, ruling 25)**: `u64`/`i64` in method args and results, event data and `AppError` fields are canonical decimal strings; bytes are base64url without padding; use `calimero_sdk::json::{u64_str, i64_str, opt_u64_str, opt_i64_str, bytes_b64url, opt_bytes_b64url}` (the macros apply them). Record fields use `json::{u64_auto, i64_auto, bytes_auto, ..}`: an integer or a byte string (major type 2) in CBOR (not human-readable), a decimal string or base64url in JSON.
- **Blob references (R8)**: a `BlobRef` is CBOR tag 51,739 (`0xCA1B`) around the blob's 32-byte SHA-256 in stored values (the host finds them and keeps the blob while one exists), and the 64-lowercase-hex id in JSON. `BlobRef::info()` / `grant(ttl)` (`env::blob_info` / `blob_grant`) reach the WIT `blobs` interface.
- **Search (spec section 7)**: `#[table(search = [..])]` names the text fields the host indexes; `Table::search(text, SearchOpts)` (views only) asks the host (`env::search_query`, the WIT `search` interface; default limit 20, at most 100) and reads each hit's record back by key, skipping one that is gone; a refusal is `StorageError::Search`.
- **Cursors** are the base64url of the last storage key, bound to the index and prefix, not signed.
- **Prefixes** longer than the index or count fields are refused (`PrefixTooLong`); `limit: 0` is an empty page.

## Test harness (`testing` feature, spec section 10)

- `TestApp::new(component, Org, now_ms)` prepares the component on the real `WasmtimeEngine` (one engine and compile cache per test process) and runs `init` as `"owner"` with no arguments (`{}`: optional params are `None`, a required one fails setup; a node passes the app's `initArgs`). `t.as_(a)` / `anonymous()` / `system()` / `api_key(id, account)` give an `As` with `call`, `view`, `confirmed()`; `Failure` is `App { code, fields }`, `Trap(TrapKind)`, `ConfirmRequired`, `BadOutput` or `Refused { status, code }`.
- The harness makes the node's checks before the app runs, with the node's codes (Ruling 32; the node is the reference). As on a node, where no access grant admits a caller without an account: every anonymous caller is refused with `401 UNAUTHENTICATED` at the access gate, before the ABI is read, `public` methods included. The harness app is an org app, so anonymous is always `Refused { 401, "UNAUTHENTICATED" }`, and an account the org does not hold (never in it, or removed) is `Refused { 404, "NOT_FOUND" }` (which does not confirm the app exists). A guest reaches the app, whose own guard decides (`App { "Forbidden" }`). Then call arguments over the node's 512 KiB (`Refused { 413, "ARGS_TOO_LARGE" }`, Ruling 30). Then the ABI's checks, in the node's order and with its codes (`node::abi_check`): `UnknownMethod` (also any reserved `__` name), `WrongKind` for `init` and timers (as a call or a view), `ConfirmNotAView`, `NotAView`, `Forbidden` for System without `allowSystem`, `ConfirmRequired`; pinned by `rooms.json`, which the cluster runs too. Typed client errors such as `LoginRequired` belong in the client SDK, mapped from the HTTP status in one place (not this milestone).
- It plays the executor: the diff is applied only on `Ok`; each logged invocation gets a fresh `id_seq` (`id_term` 1) and a seed derived from `t.seed(n)`; views see the last logged entry's timestamp (D19). Before running it applies the ABI checks a node makes: a `confirm` method needs `.confirmed()` (else `ConfirmRequired`) and is never a view (`ConfirmNotAView`); a method without `allowSystem` refuses `system()` (`Forbidden`). Anonymous callers never get this far (the access gate above).
- `t.tick(method)` runs the timer as `System` for the slot at the current time; `previous` is the last tick of the same method. A tick that does not time out counts as applied (D34).
- Events: `events_for(account)` resolves audiences when asked (R9); `remove_member` first fixes who org events so far reached, so earlier events stay with the leaver and later ones do not reach it. 
- `export_state()` is deterministic CBOR (RFC 8949 4.2.1): a map of stored key (generation prefix included) to value, byte strings, ordered by encoded key bytes. The TypeScript harness must produce the same bytes.
- What the harness org supports: one org (`ORG_ID`) with the owner (`"owner"`, role Owner), `admins`, `members`, `guests` (role checks, `org_role`, `orgs_of`), and `Org::teams([("id", ["acct", ..])])` (`in_team`, `team_exists`, `Team` audiences; a team needs no org role). `Org` audiences reach members, admins and the owner, not guests; `OrgAdmins` reaches admins and the owner. No partner orgs, no second org.
- Timeouts are not logged (D23): they consume no `id_seq` and do not move the last entry time. A result or event payload that is not JSON gives `Failure::BadOutput` and applies nothing.
- `run_scenario(t, path)` runs the neutral JSON scenario (format in `testing/scenario.rs`; `expect` takes `ok`, `error` (+ exact `fields`), `trap`, `confirmRequired` or `refused` (the node's API code of a refusal before the app ran, e.g. `"UNAUTHENTICATED"`, `"NOT_FOUND"`); a tick always runs as System and refuses `as`; `"save": "name"` stores a step's ok result and a string that is exactly `$` plus a name (`[A-Za-z_][A-Za-z0-9_]*`) in later `args`/`expect` is replaced by it (other strings, like `"$5 lunch"`, stay literal; `save` on tick/advance/removeMember is an error), so scenarios can name ids an app mints; a string that is exactly `@` plus a name in `args`/`expect` is that account as the app sees it: its name here, its account id on a cluster (`crates/node/tests/it/rooms.rs` runs the same files)).
- Upgrades: `t.upgrade(component)` switches the app's code as a node's `UpgradeApp` does, code only: state, org, clock, events, blobs and files are kept and nothing runs (no `#[app::migrate]` in this version); a component that does not prepare is `Refused { 400, "BAD_BUNDLE" }` and changes nothing. `run_migration(from, to, org, now_ms, path)` starts on `from` and runs a scenario whose one `{ "op": "upgrade" }` step switches to `to` (variables carry across; `run_scenario` refuses `upgrade`). Feature `releases`: `release_component(mpk, service)` is a signed `.mpk`'s component after the node's signature and digest checks (not `minRuntimeVersion`, the node's own release); its own feature so apps without upgrade tests keep `calimero-bundle` out of their lockfiles. Test: `tests/names.rs` (the `old-name` and `renamed` guests are one app, two releases); the example is `apps/kv-store/tests/migrations.rs`.
- Size limits: writes and events past 1 MiB per run (`MAX_RUN_BYTES`) and the write after the 10,000th (`MAX_WRITES`) are refused inside the run by the same `HostCore` the node uses, as the typed `RunLimit` (below); then the node's final check of the log entry: the harness measures the entry a node would write (`calimero_app_host::entry_bytes`, JSON with keys and values in base64, pinned to the node's `entry_json` by `the_host_cores_entry_size_is_the_logs`) and a run whose entry passes `MAX_ENTRY_BYTES` (1 MiB) is `Failure::Trap(HostDenied)` with nothing applied, as on a node (`apps/fixture-kv/tests/harness.rs`, the cluster's `oversized_entry_is_host_denied`). Harness account names are shorter than a node's ids, so an entry within a few bytes of the cap can differ.
- Blobs: `t.upload_blob(bytes, mime)` records a blob as the node would on upload and returns its id; runs see it through `info`/`grant` (a grant is `"<id>.<expires_ms>"` here) and may store a `BlobRef` to it; `t.blob_refs(id)` counts the stored values referring to it. Idle expiry is the node's (not mirrored).
- Search: the harness answers `Table::search` with the node's own index: `calimero_search::records::TableSearch` built from the view's state on its first query of a table, with the node's documents and request, so hits, ranking, scores, snippets and paging are a node's (C10; `apps/fixture-kv/tests/harness.rs` `search_matches_words_and_ranks_as_a_node_does`).
- Xcalls: `t.take_xcalls()` hands out what logged `Ok` runs sent (`SentXcall { app, method, args, on_behalf_of }`, the last being the person the sending run served, whom a node runs the call as only with their grant), oldest first; `t.deliver(from, method, args)` runs one as `kind = xcall-deliver` from `Caller::App(from)`, after the node's check that the method allows `from` (`Forbidden`); `t.deliver_for(from, account, ..)` and `t.deliver_for_key(from, key_id, account, ..)` run one as a node delivers a granted call: the caller is the person (after the node's access gate for them) and `env::via()` is `from`. A run offers its own account or key, and a run another app called offers no one, as on a node; `mock_app` handlers see it as `OtherAppCall::on_behalf_of`. Grants, retries and watermarks are the node's.
- Actions: `t.as_(a).action(method, args)` starts and runs one at once as `a`; a call of an action method only starts it (`{"actionId"}`), and `t.run_started_actions()` runs those and the ones `start_action` queued, each as its starter. The action's views and calls run on the harness itself (lent to the run, `HarnessAction`), with the node's checks (`allow(action)` reachable only from an action); its HTTP goes to `t.mock_http(host, handler)` (`HttpRequest` → `HttpResponse`), a host without one fails the fetch. Retries, the D27 replay of sub-call keys and the 10 s budget are the node's.
- Synchronous xcalls: `t.mock_app(app, handler)` answers the app's synchronous xcalls to `app` (`OtherAppCall { view, method, args, key, batch }` → `Ok(result)` or `Err(failure JSON)`; `batch` is which of the run's `xcall.batch`es it came in, from 0, so a test sees what was joined); an app without one fails the xcall. The harness runs a batch's requests one after another, after the same `HostCore` limits and keys the node applies (`apps/fixture-kv/tests/harness.rs`). The target's checks and its replay of keys are the node's.
- Not yet: migrations (`upgrade_to`).
