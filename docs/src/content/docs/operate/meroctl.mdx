`meroctl` is the command line for Calimero nodes. It keeps v1's command tree
over the node API, through `calimero-client`: before anything is
sent it fetches the node's attestation and judges the quote, then every request
travels in the sealed channel. The source is `crates/meroctl/src`.

| v1 name | What it is now |
| --- | --- |
| application (`app`) | a signed package, installed once per cluster |
| context (`context`) | an app instance |
| namespace (`namespace`) | an organization |
| group (`group`) | a team of an organization |
| identity (`account`) | an account; each passkey is one of its devices |

Output is JSON, pretty-printed. Commands that stream (`context watch`,
`context presence stream`, `ops metrics`, `blob download` to stdout, `app
watch`, `dev`) print their own lines.

## Global arguments

| Flag | Environment | Default | Meaning |
| --- | --- | --- | --- |
| `--home PATH` | `CALIMERO_HOME` | `~/.calimero` | Directory for meroctl's saved nodes and sessions (`{home}/meroctl/`). |
| `--api URL` | `CALIMERO_API` | none | The node's URL (any node of the cluster). |
| `--node ALIAS` | | the default saved node | A node saved with `node add`. Conflicts with `--api`. |
| `--allow-mock` | | off | Trust mock quotes (development clusters such as `merod local`). A flag only, never read from the environment; `node add --allow-mock` remembers it for one saved node. |
| `--allow-debug-profiles` | | off | Trust a release's debug profiles (the host can read a debug image's memory). |
| `--tee-profiles NAME,...` | `CALIMERO_TEE_PROFILES` | none | Image profiles a real node's signed mero-tee release must list it under. Without any, every real quote is refused. |
| `--min-release VERSION` | `CALIMERO_MIN_RELEASE` | `2.3.109` | The oldest mero-tee release to trust. |
| `--api-key KEY` | `CALIMERO_API_KEY` | none | Authenticate with this API key instead of a saved session. |
| `--ops-token TOKEN` | `CALIMERO_OPS_TOKEN` | none | The operator's token, for `ops` commands. |

Which node: `--api`, else `--node`, else the default saved node. Which
credential: `--api-key`, else the session saved for that node's URL (refreshed
when it is within 30 seconds of expiring), else none, and the node says what
the request needs.

A `CONTEXT` argument is an alias of the signed-in account or an app id (a
context id works too). With no credential, it is used as given.

### Approvals on a development cluster

What an owner approves takes `--dev-passkey FILE`: a passkey kept in a file,
which only a development cluster's `localhost` relying party accepts.
Without it, the command sends the request plainly and the node answers
`412 CONFIRM_REQUIRED`: on a real cluster the owner approves in a browser.
That holds for `context update`, `context transfer`, `namespace delete`, `namespace outbound`,
`namespace approve-release`, `account outbound`, `account approve-release`,
`group upgrade trigger` and `group upgrade retry`.

## node

Saved nodes, in `{home}/meroctl/nodes.json` (mode `0600`). No network.

| Command | Meaning |
| --- | --- |
| `node add NAME URL [--allow-mock]` | Save a node. The first one saved becomes the default. `--allow-mock` trusts its mock quote. A name is letters, digits, `-` and `_`. |
| `node remove NAME` (`rm`) | Forget a saved node. |
| `node use NAME` | Make a saved node the default. |
| `node list` (`ls`) | The saved nodes and the default. |

## login, logout, whoami, attest

| Command | Route | Meaning |
| --- | --- | --- |
| `login --dev-passkey FILE [--name NAME] [--origin URL]` | `/auth/passkey/register/*` or `/auth/passkey/login/*` | Sign in with a file passkey, or sign up when `FILE` does not exist (`--name`, default `developer`, names the account). `--origin` (default `http://localhost:3000`) must be one the cluster allows. Needs `--allow-mock`: on a real cluster use an API key. Saves the session for the node. |
| `logout [--all]` | `/auth/logout-all` with `--all` | Forget the saved session; `--all` first ends every session of the account. |
| `whoami` | `GET /auth/me` | Who the requests run as. |
| `attest [-c CONTEXT]` | `GET /attestation`, `GET /apps/{app}/attestation` | The node's attestation document; with `--context`, every replica of that app verified, their receipt keys and the governance they attest. |
| `attest-release [--file FILE --nonce HEX]` | `GET /attestation/release` | Verify a [release attestation](/operate/merod/#attest) (`merod attest`): fetched from the node's URL over a fresh nonce (a booting TD's `merod attest --serve`), or read from `FILE` with the nonce it was made over. Judged with `--allow-mock`, `--tee-profiles` and `--min-release` like any quote; needs no session. Prints the claim, the verified registers and the profile they matched. |

## app

Signed packages (v1's applications). An application is installed once on the
cluster and verified on every node that runs it.

| Command | Route | Meaning |
| --- | --- | --- |
| `app install PACKAGE[@VERSION] [--version V]` | `POST /packages/install` | Install a release from the node's registry. The version is required, as `@V` or `--version`. |
| `app install --path FILE` | `POST /packages` or `POST /bundles` | Upload a signed `.mpk`; any other file is uploaded as a raw WASM bundle (development clusters only) and its hash printed. |
| `app list` (`ls`, `list-packages`) | `GET /packages` | Installed applications and their versions. |
| `app get PACKAGE` | `GET /packages/{package}` | One installed application. |
| `app versions PACKAGE` (`list-versions`) | `GET /packages/{package}` | Its installed versions. |
| `app get-latest-version PACKAGE` | `GET /packages/{package}` | Its newest installed version. |
| `app uninstall PACKAGE [--version V]` | `DELETE /packages/{package}[/{version}]` | Uninstall one version or the whole application. Refused while a context runs it. |
| `app watch --path FILE --dev-passkey FILE [-c CONTEXT]... [--once] [--interval-ms MS]` | uploads, then `POST /apps/{app}/upgrade` | Push a build now, then on every save. A `.mpk` is installed and this account's contexts of its package (or the `--context`s named) are updated to its version; a raw `.wasm` updates only the `--context`s named. `--interval-ms` defaults to `500`. |

## context

App instances (v1's contexts).

| Command | Route | Meaning |
| --- | --- | --- |
| `context create --name NAME (--package P [--version V] \| --bundle HASH \| --path FILE) [options]` | `POST /apps` | Create a context. `--path` installs a `.mpk` (or a development `.wasm`) first. See the options below. |
| `context list [--package P]` (`ls`) | `GET /apps[?package=P]` | Contexts this account reaches. |
| `context get CONTEXT` | `GET /apps/{app}` | One context. |
| `context delete CONTEXT` (`del`) | `DELETE /apps/{app}` | Delete a context (its owner or an org admin). |
| `context transfer CONTEXT ACCOUNT [--dev-passkey F]` | `POST /apps/{app}/transfer` | Hand the context to another account (its owner, with a passkey; an org's context only to a member of the org). |
| `context update CONTEXT [--version V] [--package P] [--service S] [--bundle HASH] [--migrate EXPORT] [--dev-passkey FILE]` | `POST /apps/{app}/upgrade` | Move to another release or bundle, migrating state where the ABIs say how. `--bundle` conflicts with `--version` and `--package`. The owner approves. |
| `context watch CONTEXT [--from N] [--limit N]` (`ws`) | `GET /apps/{app}/events` | Print committed events from index `--from` (default `0`), then live ones, as JSON lines; stop after `--limit`. |
| `context alias add ALIAS CONTEXT` (`new`, `create`) | `PUT /auth/aliases/{alias}` | Name a context for this account. |
| `context alias remove ALIAS` (`rm`, `del`, `delete`) | `DELETE /auth/aliases/{alias}` | Remove an alias. |
| `context alias get [ALIAS]` | `GET /auth/aliases/{alias}` | Resolve an alias (default `default`). |
| `context alias list` (`ls`) | `GET /auth/aliases` | This account's aliases. |
| `context use CONTEXT` | `PUT /auth/aliases/default` | Make a context the default (the alias `default`). |
| `context access CONTEXT owner\|org\|team\|accounts\|public [--group TEAM] [--account ID]...` | `POST /apps/{app}/access` | Who reaches the context. `team` needs `--group`; `accounts` takes `--account` once per account. |
| `context metadata CONTEXT JSON` | `POST /apps/{app}/metadata` | Set the context's metadata; `null` clears it. |
| `context storage CONTEXT` | `GET /apps/{app}/storage` | Keys, bytes and blobs the context holds. |
| `context abi CONTEXT` | `GET /apps/{app}/abi` | The ABI of the bundle it runs. |
| `context presence list CONTEXT` (`ls`) | `GET /apps/{app}/presence` | Who is present now (ephemeral, never stored). |
| `context presence publish CONTEXT --seq N [--state HEX]` | `POST /apps/{app}/presence` | Publish this device's presence; no `--state` retracts it. |
| `context presence stream CONTEXT [--limit N]` | `GET /apps/{app}/presence/stream` | The snapshot, then each change, as JSON lines. |

`context create` options:

| Flag | Meaning |
| --- | --- |
| `--name NAME` | Required. The context's name. |
| `--package P` | An installed application. Conflicts with `--bundle` and `--path`. |
| `--version V` | With `--package`: the release; default the newest installed. |
| `--service S` | The service, for a multi-service application. |
| `--bundle HASH` | A raw bundle's hash (development clusters). Conflicts with `--path`. |
| `--path FILE` | A `.mpk`, or a development `.wasm`, installed first. |
| `--params JSON` | Arguments for the app's `init`. |
| `--namespace ORG` | Create it in this organization. |
| `--group TEAM` | With `--namespace`: reached by this team's members (`access: team`). |
| `--confirm METHOD` | A method that needs a passkey confirmation per call; repeat for each. |
| `--alias ALIAS` | Also name it with this alias. |

## call

```bash
meroctl call -c CONTEXT METHOD [--args JSON] [--view [--min-index N]]
             [--idempotency-key KEY] [--dev-passkey FILE]
```

| Flag | Default | Meaning |
| --- | --- | --- |
| `-c, --context CONTEXT` | required | The context. |
| `METHOD` | required | The method. |
| `--args JSON` | `{}` | JSON arguments. |
| `--view` | off | Read only (`POST /apps/{app}/views`): no write, answered by the leader. |
| `--min-index N` | none | With `--view`: any replica that has applied index `N` may answer (a stale read). |
| `--idempotency-key KEY` | none | Retries with the same key are answered once. |
| `--dev-passkey FILE` | none | For a method that needs a passkey confirmation per call (development clusters). |

A call without `--view` is `POST /apps/{app}/intents`. Both answers carry a
receipt signed by the answering node.

## blob

A context's blobs.

| Command | Route | Meaning |
| --- | --- | --- |
| `blob list -c CONTEXT` (`ls`) | `GET /apps/{app}/blobs` | The context's blobs. |
| `blob upload FILE -c CONTEXT` | `POST /apps/{app}/blobs` | Upload a file; prints its id. |
| `blob download ID -c CONTEXT [-o FILE]` | `GET /apps/{app}/blobs/{id}` | Write a blob to `--output`, or to standard output. |

## namespace

Organizations (v1's namespaces). Alias: `ns`. `ROLE` is `guest`, `member`,
`admin` or `owner`; `JOIN` is `open` (whoever reaches the parent is a member)
or `restricted` (only the members added).

| Command | Route | Meaning |
| --- | --- | --- |
| `namespace create NAME` | `POST /orgs` | Create an organization. |
| `namespace get ORG` | `GET /orgs/{org}` | One organization. |
| `namespace list` (`ls`) | `GET /auth/me` | The organizations this account belongs to, with its role. |
| `namespace delete ORG [--dev-passkey FILE]` | `DELETE /orgs/{org}` | Delete it with its teams, invites and contexts (the owner's). |
| `namespace invite ORG [--role ROLE] [--group TEAM]... [--ttl-secs N] [--uses N]` | `POST /orgs/{org}/invites` | Make an invitation token. `--role` defaults to `member`; `--group` adds teams the invitee joins. |
| `namespace join TOKEN` | `POST /invites/{token}/redeem` | Join with an invitation token. |
| `namespace leave ORG` | `DELETE /orgs/{org}/members/{me}` | Leave the organization. |
| `namespace groups ORG` | `GET /orgs/{org}` | The organization's teams. |
| `namespace create-group ORG NAME [--parent TEAM] [--join JOIN]` | `POST /orgs/{org}/teams` | Create a team; `--join` defaults to `restricted`. |
| `namespace members list ORG` (`ls`) | `GET /orgs/{org}` | Its members. |
| `namespace members add ORG ACCOUNT [--role ROLE]` (`set-role`) | `POST /orgs/{org}/members` | Add a member or change their role (default `member`). `owner` moves ownership. |
| `namespace members remove ORG ACCOUNT` (`rm`) | `DELETE /orgs/{org}/members/{account}` | Remove a member. |
| `namespace metadata get ORG` | `GET /orgs/{org}` | The organization's metadata. |
| `namespace metadata set ORG JSON` | `POST /orgs/{org}/metadata` | Replace it. |
| `namespace member-metadata ORG ACCOUNT JSON` | `POST /orgs/{org}/members/{account}/metadata` | Set a member's metadata (theirs, or an admin's); `null` clears it. |
| `namespace capabilities ORG BITS [--account ID \| --group TEAM]` | `POST /orgs/{org}/capabilities` | Set the capability bits of a member, of a team's members, or (neither) the organization's default. |
| `namespace outbound ORG --package P [--prefix URL]... [--replace] [--dev-passkey FILE]` | `POST /orgs/{org}/outbound` | Approve URL prefixes the package's publisher may call out to from the organization's contexts (default: every prefix its latest release declares). `--replace` sets exactly these, which is how one is revoked. Where the owner holds outbound approvals. |
| `namespace approve-release ORG VERSION [--dev-passkey FILE]` | `POST /orgs/{org}/releases` | Approve a mero-tee release to hold the organization's contexts. Where the owner holds release approvals. |

## group

An organization's teams (v1's groups). `ROLE` is `lead`, `member` or
`read-only`.

| Command | Route | Meaning |
| --- | --- | --- |
| `group get ORG TEAM` | `GET /orgs/{org}/teams/{team}` | One team. |
| `group update ORG TEAM [--name NAME] [--join JOIN]` | `POST /orgs/{org}/teams/{team}` | Rename it or change who may join. |
| `group delete ORG TEAM` | `DELETE /orgs/{org}/teams/{team}` | Delete it with the teams below it and their contexts. |
| `group reparent ORG TEAM (PARENT \| --top)` | `POST /orgs/{org}/teams/{team}` | Move it under another team, or to the top. |
| `group subgroups ORG TEAM` | `GET /orgs/{org}` | The teams directly below it. |
| `group members list ORG TEAM` (`ls`) | `GET /orgs/{org}/teams/{team}` | Its members and read-only members. |
| `group members add ORG TEAM ACCOUNT [--role ROLE] [--capabilities BITS]` (`set-role`) | `POST /orgs/{org}/teams/{team}/members` | Add a member or change their role (default `member`) or capabilities. |
| `group members remove ORG TEAM ACCOUNT` (`rm`) | `DELETE /orgs/{org}/teams/{team}/members/{account}` | Remove a member. |
| `group metadata ORG TEAM JSON` | `POST /orgs/{org}/teams/{team}` | Set the team's metadata. |
| `group settings ORG TEAM --capabilities BITS` | `POST /orgs/{org}/capabilities` | The capabilities every member of the team gets. |
| `group leave ORG TEAM` | `DELETE /orgs/{org}/teams/{team}/members/{me}` | Leave the team. |
| `group upgrade trigger ORG --package P --version V [--group TEAM [--cascade]] [--migrate EXPORT] [--dev-passkey FILE]` | `POST /orgs/{org}/upgrade` | Move the organization's contexts of `P` (or one team's, with `--cascade` its subtree) to a release, as one run the owner approves once. |
| `group upgrade status ORG RUN` | `GET /orgs/{org}/upgrades/{run}` | Follow a run. |
| `group upgrade retry ORG RUN [--dev-passkey FILE]` | `POST /orgs/{org}/upgrades/{run}/retry` | Run its failed contexts again, as a new run. |

## ops

The operator's commands. Every one needs `--ops-token` (or
`CALIMERO_OPS_TOKEN`). The Ops API has no read path into apps' data. Decisions
the deployment gave the operator are made here; the node answers `403` for the
others.

| Command | Route | Meaning |
| --- | --- | --- |
| `ops status` | `GET /ops/status` | This node, the system group's and hosted groups' Raft status, governance, fleet and counts. |
| `ops metrics` | `GET /ops/metrics` | Prometheus text. |
| `ops add-node ID ADDR [--zone Z]` | `POST /ops/nodes` | Register a node so the system group admits it as a learner. `ADDR` is its URL. |
| `ops remove-node ID` | `DELETE /ops/nodes/{id}` | Remove a node no app keeps a replica on; run against the system leader. |
| `ops move CONTEXT --replicas ID,...` | `POST /ops/apps/{app}/replicas` | Move a context to these replica node ids. A follower answers `421 NOT_LEADER`; meroctl retries at the leader it names. |
| `ops backup` | `POST /ops/backup` | Write encrypted snapshots of the contexts this node leads now. |
| `ops quotas` | `GET /ops/quotas` | The per-account quotas. |
| `ops set-quotas JSON` | `POST /ops/quotas` | Replace them. |
| `ops release VERSION [--withdraw]` | `POST /ops/releases` | Approve (or withdraw) a mero-tee release for every app, where the operator holds release approvals. |
| `ops outbound --package P [--prefix URL]... [--replace]` | `POST /ops/outbound` | Approve outbound prefixes cluster-wide, where the operator holds outbound approvals. |
| `ops packages` | `GET /ops/packages` | The applications the operator installed (not the accounts'). |
| `ops install PACKAGE[@VERSION] [--version V]` / `ops install --path FILE` | `POST /ops/packages/install`, `POST /ops/packages` | Install a release for the operator's upgrades, from the registry or a signed `.mpk`. |
| `ops uninstall PACKAGE [--version V]` | `DELETE /ops/packages/{package}[/{version}]` | Uninstall what the operator installed. |
| `ops upgrade CONTEXT [--version V] [--package P] [--service S] [--bundle HASH] [--migrate EXPORT]` | `POST /ops/apps/{app}/upgrade` | Update a context to an installed release, where the operator holds app upgrades. |
| `ops upgrade-namespace ORG --package P --version V [--group TEAM [--cascade]] [--migrate EXPORT]` | `POST /ops/orgs/{org}/upgrade` | Update an organization's contexts (or one team's) to a release; follow it with `group upgrade status`. |

<Aside type="note">
  `ops move` and `ops upgrade` pass `CONTEXT` to the node as given (an app id
  or a context id); they do not resolve aliases.
</Aside>

## raw

```bash
meroctl raw METHOD PATH [BODY]
```

Any API route, through the same attested, sealed client. `METHOD` is `get`,
`post`, `put` or `delete`; `BODY` is JSON (default `{}` for `post` and `put`).
Use it for what no command covers, such as `POST /auth/apikeys` with
`methods` or `allowConfirm`. It cannot answer a `412 CONFIRM_REQUIRED`: a route
that needs a passkey assertion needs a command with `--dev-passkey`, or a
browser. See the
[node API reference](/operate/admin-api/).

## Not carried over from v1

`context sync` and `group sync` (Raft replicates), `context identity`,
`account pair-*`, `seal-to` and `device-init` (a passkey is the device),
`peers` (there is no gossip network) and `tee fleet-join` (`ops add-node`)
have no meaning on a cluster.

## Example session

```bash
merod local                                         # in another terminal
meroctl node add local http://127.0.0.1:2501/ --allow-mock
meroctl login --dev-passkey ./dev-passkey.json --name ada
meroctl app install --path ./kv-store.mpk
meroctl context create --package com.example.kv --name notes --alias notes
meroctl call -c notes set --args '{"key":"a","value":"1"}'
meroctl call -c notes get --args '{"key":"a"}' --view
meroctl --ops-token "$TOKEN" ops status
```
