`meroctl` is the one command line for Calimero: it starts an app
(`app new`), builds, packs, signs and publishes it (`app build`, `app pack`,
`app publish`), runs a development cluster around it (`local`), reaches
Calimero Cloud (`cloud`), and talks to nodes. It replaces `mero-app-build`,
`mero-sign`, `mero-compute` and `scripts/pack-component.py`, which stay one
release as deprecated shims. The commands that talk to a node go through the
node API with `calimero-client`: before anything is sent it fetches the node's
attestation and judges the quote, then every request travels in the sealed
channel. Each
command calls the client's method for its route, generated from the node's
[API document](/operate/api-reference/), so the route each one names below is
the operation it calls. The source is `crates/meroctl/src`.

Its command names differ from the rest of these docs for a few objects
([glossary](/protocol/glossary/)):

| Command | What it manages |
| --- | --- |
| `app` | signed packages (applications), installed once per cluster |
| `context` | app instances |
| `namespace` | organizations |
| `group` | an organization's teams |
| `account` | the signed-in account; each passkey is one of its devices |
| `local` | a development cluster on this machine, and the build loop around it |
| `cloud` | Calimero Cloud (organizations, clusters), and a cluster's compute |

Output is JSON, pretty-printed: the route's answer as the client reads it,
with any field the client's types do not name kept as the node sent it.
Commands that stream (`context watch`, `cloud compute pipeline watch`,
`context presence stream`, `ops metrics`, `blob download` to stdout, `app
watch`, `local dev`) print their own lines, as do `app codegen`, `app abi
diff` and `app signer`. The commands that need no node (`app new`, `app build`,
`app codegen`, `app abi`, `app signer`, `app pack`, `app sign`, `app inspect`,
`app publish`, `local`, `cloud` but `cloud compute`) never read `--node` or
`--api`.

## Global arguments

| Flag | Environment | Default | Meaning |
| --- | --- | --- | --- |
| `--home PATH` | `CALIMERO_HOME` | `~/.calimero` | Directory for meroctl's saved nodes and sessions (`{home}/meroctl/`). |
| `--api URL` | `CALIMERO_API` | none | The node's URL (any node of the cluster). |
| `--node ALIAS` | | the default saved node | A node saved with `node add`, or a node's URL (`http://` or `https://`, as `--api`). Conflicts with `--api`. |
| `--allow-mock` | | off | Trust mock quotes (development clusters such as `merod local`). A flag only, never read from the environment; `node add --allow-mock` remembers it for one saved node. |
| `--allow-debug-profiles` | | off | Trust a release's debug profiles (the host can read a debug image's memory). |
| `--tee-profiles NAME,...` | `CALIMERO_TEE_PROFILES` | none | Image profiles a real node's signed mero-tee release must list it under. Without any, every real quote is refused. |
| `--min-release VERSION` | `CALIMERO_MIN_RELEASE` | `2.3.109` | The oldest mero-tee release to trust. |
| `--api-key KEY` | `CALIMERO_API_KEY` | none | Authenticate with this API key instead of a saved session. |
| `--ops-token TOKEN` | `CALIMERO_OPS_TOKEN` | none | The operator's token, for `ops` commands. |
| `--operator-key-file FILE` | `CALIMERO_OPERATOR_KEY_FILE` | none | The operator's Ed25519 key (32-byte seed, hex; the node has its public half from `merod --operator-key`): `ops release`, `ops outbound`, `ops upgrade`, `ops upgrade-namespace`, `ops add-node`, `ops remove-node`, `ops move`, `ops restore`, `ops backup-key --public-key`, `ops set-quotas`, `ops set-pools` and `ops set-prices` sign the decision with it when the node asks (`428 OPERATOR_SIGNATURE_REQUIRED`). Without it, meroctl says to pass it. |

Which node: `--api`, else `--node`, else the default saved node. Which
credential: `--api-key`, else the session saved for that node's URL (refreshed
when it is within 30 seconds of expiring), else none, and the node says what
the request needs.

A `CONTEXT` argument is an alias of the signed-in account or an app id (a
context id works too). With no credential, it is used as given.

### Approvals on a development cluster

What an owner approves takes `--dev-passkey FILE`: a passkey kept in a file,
which only a development cluster's `localhost` relying party accepts.
Without it, the command sends the request plainly and the node answers
`412 CONFIRM_REQUIRED`: on a real cluster the owner approves in a browser.
That holds for `call` (a confirm method), `context update`, `context transfer`,
`context move`, `namespace delete`, `namespace outbound`,
`namespace approve-release`, `namespace invite`, `namespace leave`,
`namespace members add`, `namespace members remove`, `namespace capabilities`,
`account outbound`, `account approve-release`, `account api-key create`,
`account api-key revoke`, `account device revoke`, `group delete`,
`group members add`, `group members remove`, `group settings`, `group leave`,
`group upgrade trigger`, `group upgrade retry`, `app origins add`,
`app origins remove` and `raw`. `app watch`, `dev start` and `dev watch`
require it; `local dev` signs up a deployer of its own. `account device add` takes `--approve-with FILE`, a passkey file
the account already has.

## node

Saved nodes, in `{home}/meroctl/nodes.json` (mode `0600`). No network.

| Command | Meaning |
| --- | --- |
| `node add NAME URL [--allow-mock]` | Save a node. The first one saved becomes the default. `--allow-mock` trusts its mock quote. A name is letters, digits, `-` and `_`. |
| `node remove NAME` (`rm`) | Forget a saved node. |
| `node use NAME` | Make a saved node the default. |
| `node list` (`ls`) | The saved nodes and the default. |

## login, logout, whoami, attest

| Command | Route | Meaning |
| --- | --- | --- |
| `login --dev-passkey FILE [--name NAME] [--origin URL]` | `/auth/passkey/register/*` or `/auth/passkey/login/*` | Sign in with a file passkey, or sign up when `FILE` does not exist (`--name`, default `developer`, names the account). `--origin` (default `http://localhost:3000`) must be one the cluster allows. Needs `--allow-mock`: on a real cluster use an API key. Saves the session for the node. |
| `logout [--all]` | `/auth/logout-all` with `--all` | Forget the saved session; `--all` first ends every session of the account. |
| `whoami` | `GET /auth/me` | Who the requests run as. |
| `attest` (`attest node`) | `GET /attestation` | The node's attestation document. |
| `attest app CONTEXT` (was `attest --context`) | `GET /apps/{app}/attestation` | Every replica of that app verified, their receipt keys and the governance they attest. |
| `attest release [--file FILE --nonce HEX]` (was `attest-release`) | `GET /attestation/release` | Verify a [release attestation](/operate/merod/#attest) (`merod attest`): fetched from the node's URL over a fresh nonce (a booting TD's `merod attest --serve`), or read from `FILE` with the nonce it was made over. Judged with `--allow-mock`, `--tee-profiles` and `--min-release` like any quote; needs no session. Prints the claim, the verified registers and the profile they matched. |

## app

Signed packages, from an empty directory to an install. Making and shipping
one needs no node:

| Command | Meaning |
| --- | --- |
| `app new DIR [--template T] [--ref R] [--no-git]` | Start a project from `apps/<T>` of [calimero-network/apps](https://github.com/calimero-network/apps) at branch or tag `R` (default `kv-store` at `main`): a sparse, shallow clone of the app, the shared `packages/` and `tools/` it builds with, and the root files that pin its versions, with the history dropped and a fresh `git init`. `DIR` must not exist or be empty. Needs `git`. The app's README says how to run it (`meroctl local dev apps/<T>`). |
| `app build [DIR] [--out FILE] [--compute-out FILE] [--target-dir DIR]` | Build the crate (default `.`) into a `calimero:app` component (`wasm32-wasip2`, the ABI lifted where the node reads it), default `DIR/app.component.wasm`, and its compute component when it has compute methods (default `compute.component.wasm` beside it). |
| `app codegen --abi FILE --lang ts\|python\|swift\|kotlin\|openapi [-o DIR] [--name N] [--package P] [--service S] [--kotlin-serialization-plugin] [--no-openapi]` | The app's OpenAPI document and a typed client ([Typed clients](/build/guides/typed-clients/)). `FILE` is a component, an `.mpk`, a `manifest.json` or ABI JSON. |
| `app abi show FILE [--service S]` | The ABI as JSON. |
| `app abi diff OLD NEW [--service S] [--json]` | What changed between two releases; exit code 1 when a change breaks existing callers ([App interface](/build/app-abi/)). |
| `app signer new FILE [--force]` / `app signer id FILE` | A new Ed25519 signing key (written owner-only), and its `did:key` signer id. A package's identity is its package id and its signer. |
| `app pack [DIR] [--wasm F] [--compute F] [--pipeline F]... [--frontend DIR] [--frontend-entry E] [--no-frontend] [--outbound URL]... [--upgrades owner\|publisher] [--package P] [--name N] [--description D] [--icon PNG] [--category C] [--app-version V] [--min-runtime-version V] [--key FILE] [--previous OLD] [--out FILE]` | Write the manifest the node reads, sign it, and write it with every file it names as an `.mpk`. With the crate `DIR`, its `[package.metadata.calimero]` and `version` fill what the flags leave out: `package`, `min-runtime-version`, `frontend-dir`, the display metadata a registry lists a new package by (`name`, `description`, `icon` (a PNG), `category`, `tags`, `author`, `license`, `guide`), `slug`, the links (`frontend`, `github`, `docs`, `frontend-aliases`), `outbound` and `upgrades`; `--name`, `--description`, `--icon` and `--category` set them without a crate, the components are built unless `--wasm`/`--compute` name them, and the default output is `DIR/dist/<package>-<version>.mpk`. A frontend is checked with the node's rules (paths, types, `MAX_FRONTEND_BYTES`, the entry) and the HTML rules its CSP enforces. Without `--key` the development key signs, which a public registry refuses. `--previous` reports ABI changes against the last release first. |
| `app sign MANIFEST (--key FILE \| --dev) [--previous OLD]` | Sign a `manifest.json` in place. |
| `app inspect FILE.mpk` | Open the bundle as a node does (signature, every artifact's hash) and print `verified`, `signerId`, `bundleHash` and the manifest. |
| `app publish FILE.mpk [--registry URL] [--api-key KEY] [--org ORG] [--cloud URL] [--public]` | Publish to the app registry (`CALIMERO_REGISTRY_URL`, default `https://apps.calimero.network`; `POST /api/bundles/push` with the signed manifest and the bundle, the key `CALIMERO_REGISTRY_API_KEY` as a bearer token, over `https` only). With `--org`, the key is a Calimero Cloud organization's (`ck_live_…`, scope `registry:publish`), traded at the Cloud (`CALIMERO_CLOUD_URL`) for a short publish token first. A new package is private unless `--public`. The registry's refusal comes back with its code (`version_not_allowed`, `invalid_signature`, ...). |

An application is installed once on the cluster and verified on every node
that runs it. `meroctl package` is the same command (`meroctl package origins
list PACKAGE`).

| Command | Route | Meaning |
| --- | --- | --- |
| `app install PACKAGE[@VERSION] [--version V]` | `POST /packages/install` | Install a release from the node's registry. The version is required, as `@V` or `--version`. |
| `app install --path FILE` | `POST /packages` or `POST /bundles` | Upload a signed `.mpk`, or any other file as a raw WASM bundle (its hash printed). Development clusters (`--dev`) only; production installs `PACKAGE@VERSION` from the registry. |
| `app list` (`ls`, `list-packages`) | `GET /packages` | Installed applications and their versions. |
| `app get PACKAGE` | `GET /packages/{package}` | One installed application. |
| `app versions PACKAGE` (`list-versions`) | `GET /packages/{package}` | Its installed versions. |
| `app get-latest-version PACKAGE` | `GET /packages/{package}` | Its newest installed version. |
| `app pipelines PACKAGE [--version V]` | `GET /packages/{package}/{version}/pipelines` | The pipelines a version registered (default: the newest): per name, `hash`, `worstCaseFuel`, the `modules` it pins and the canonical `pipeline`. |
| `app uninstall PACKAGE [--version V]` | `DELETE /packages/{package}[/{version}]` | Uninstall one version or the whole application. Refused while a context runs it. |
| `app watch --path FILE --dev-passkey FILE [-c CONTEXT]... [--once] [--interval-ms MS]` | uploads, then `POST /apps/{app}/upgrade` | Push a build now, then on every save. A `.mpk` is installed and this account's contexts of its package (or the `--context`s named) are updated to its version; a raw `.wasm` updates only the `--context`s named. `--interval-ms` defaults to `500`. |
| `app origins list PACKAGE` (`ls`) | `GET /package-origins/{package}` | The web origins registered for the application: each `origin`, its `rpId`, `addedBy`, `addedAt` and `served` (whether the cluster serves the frontend there). Its manager's only. |
| `app origins add PACKAGE ORIGIN [--rp-id ID] [--served] [--dev-passkey FILE]` | `POST /package-origins/{package}` | Register a web origin whose pages may sign people in to the application ([registered origins](/protocol/identities/#registered-origins)). `ORIGIN` is `https://host[:port]` as a browser writes it (`http` only on a `localhost` name, on a `--dev` node). `--rp-id` is the passkey relying party there: the origin's host (the default) or a parent domain of it, never the cluster's rp-id or a parent of it; passkeys made there belong to that domain. A package registers at most 8. `--served` makes it a custom domain: the cluster also serves the application's frontend there from its signed bundle (`https://host`, no port; not under the apps domain or the cluster's rp-id; at most 4 per package and 64 per cluster). The node refuses it `400 NOT_SERVING` without `--apps-domain` and `409 CLUSTER_NOT_UPGRADED` while a node runs an older release; an origin held with the other `served` is `409 ORIGIN_TAKEN` (remove it first). Browsers reach it once Calimero Cloud holds its certificate and route (`docs/specs/custom-domains.md`). |
| `app origins remove PACKAGE ORIGIN [--dev-passkey FILE]` (`rm`) | `DELETE /package-origins/{package}` | Remove a registered origin; the sessions opened there end. |

The application's manager handles its origins: where its signing key is bound
to a publisher organization, that organization's org-wide `MANAGE_APPLICATION`
holders, else the account that installed it first. Each change carries the
manager's passkey consent (`package:{package} / __add_origin / { origin, rpId }`,
`{ origin, rpId, served: true }` for a served one,
`__remove_origin / { origin }`): `--dev-passkey` on a development cluster;
without it the node answers `412 CONFIRM_REQUIRED` and nothing changes, and on
a real cluster the manager makes the change in the console (Web addresses),
where the browser holds their passkey. A frontend the cluster serves from the
bundle needs no origin here.

## cloud

Calimero Cloud's manager API (mdma). Its organizations and clusters take a
console session (Google sign-in): `cloud login` checks and keeps the session
token a signed-in console sends, in `{home}/meroctl/cloud.json` (mode `0600`),
and saves the fresh one the manager sends back on each answer
(`X-MDMA-Session-Refresh`). No node. A manager (or, for `app publish`, a
registry) that answers `404` at `/api/...` predates its unversioned routes, and
the request is sent once more at `/api/v2/...`.

| Command | Route | Meaning |
| --- | --- | --- |
| `cloud login --token TOKEN [--url URL]` | `GET /api/orgs` | Check and keep the session. `CALIMERO_CLOUD_TOKEN` and `CALIMERO_CLOUD_URL` (default `https://cloud.calimero.network`) work too. |
| `cloud logout` | | Forget the saved session. |
| `cloud orgs` | `GET /api/orgs` | Your organizations, the personal one first. |
| `cloud clusters list` (`ls`) | `GET /api/clusters` | Your dedicated clusters, each with its nodes' `public_url`. |
| `cloud clusters create NAME --size SIZE [--org ORG] [--region R]` | `POST /api/clusters` | A new dedicated cluster: an organization admin, within quota, with a payment method (`402` otherwise). |
| `cloud use CLUSTER [--as NAME]` | `GET /api/clusters` | Save the cluster's node as a meroctl node (default: named after the cluster) and make it the default, attested as a real node (no `--allow-mock`). |

## cloud compute pipeline

The old top-level `pipeline` is the same command.

A context's pipeline runs: DAGs of compute steps over sealed files, which a
package's release registers and job nodes run. `APP` is a context (alias or
id).

| Command | Route | Meaning |
| --- | --- | --- |
| `cloud compute pipeline validate FILE [--package P --version V]` | `POST /pipelines/validate` | Check a pipeline file and print every error with its path and code; exit code 1 when it is not valid. With a release, check it as that release would install it. Writes nothing. |
| `cloud compute pipeline estimate APP NAME [--input NAME=ID[,ID...]]... [--count NAME=N]...` | `POST /apps/{app}/pipelines/{name}/estimate` | Runs, fuel and cost per step for the given input file counts, `maxItems` for an input not given. Starts nothing. |
| `cloud compute pipeline run APP NAME [--input NAME=ID[,ID...]]... [--param NAME=VALUE]... [--max-cost MICRO_UNITS] [--wait]` | `POST /apps/{app}/pipelines/{name}/runs` | Start a run of a pipeline the context's release registers; prints `{ run }`, or with `--wait` the run once it is no longer running. `--max-cost` caps what the run may owe under the operator's price table. |
| `cloud compute pipeline get APP RUN` | `GET /apps/{app}/pipeline-runs/{run}` | A run's state and each step's status, runs, outputs and reason. |
| `cloud compute pipeline runs APP` | `GET /apps/{app}/pipeline-runs` | The context's recent runs, newest first. |
| `cloud compute pipeline watch APP RUN` | `GET /apps/{app}/pipeline-runs/{run}/events` | One JSON line per `snapshot`, `run` and `step` event, then the `end` event as the answer. |
| `cloud compute pipeline cancel APP RUN` | `POST /apps/{app}/pipeline-runs/{run}/cancel` | Cancel a run. |
| `cloud compute pipeline retry APP RUN [--limit STEP.FIELD=N]... [--max-cost MICRO_UNITS] [--wait]` | `POST /apps/{app}/pipeline-runs/{run}/retry` | Start a new run of an ended run's pipeline, release, inputs and params with some step limits raised (`fuel`, `memoryMib`, `wallSecs`, each within the method's caps); what already succeeded is answered from the step cache. |
| `cloud compute pipeline receipt APP RUN [--verify] [--out FILE]` | `GET /apps/{app}/pipeline-runs/{run}/receipt` | The node-signed receipt of an ended run; with `--verify`, check it under the node's attested key and compare each downloaded output with its hash. |
| `cloud compute pipeline logs APP RUN --step STEP [--index I]` | `GET /apps/{app}/pipeline-runs/{run}`, then `GET /apps/{app}/runs/{run}/logs` | Print the module log of a step's compute run (`--index`, default `0`, is its item's place), as `cloud compute logs` does. |
| `cloud compute pipeline download APP RUN [--out DIR]` | the file export routes | Download every output of every step of an ended run as `STEP-INDEX.bin`. |

```bash
meroctl cloud compute pipeline validate ./pipelines/ingest.yaml --package com.example.docs --version 1.2.0
meroctl file upload ./report.pdf -c docs                     # prints { id, size, sha256, index }
meroctl cloud compute pipeline estimate docs ingest --input pages=<file-id>
meroctl cloud compute pipeline run docs ingest --input pages=<file-id> --param lang=en --max-cost 5000000 --wait
meroctl cloud compute pipeline receipt docs <run> --verify
meroctl cloud compute pipeline download docs <run> --out ./outputs
```

## call

```bash
meroctl call -c CONTEXT METHOD [--args JSON] [--view [--min-index N]]
             [--idempotency-key KEY] [--dev-passkey FILE]
```

| Flag | Default | Meaning |
| --- | --- | --- |
| `-c, --context CONTEXT` | required | The context. |
| `METHOD` | required | The method. |
| `--args JSON` | `{}` | JSON arguments. |
| `--view` | off | Read only (`POST /apps/{app}/views`): no write, answered by the leader. |
| `--min-index N` | none | With `--view`: any replica that has applied index `N` may answer (a stale read). |
| `--idempotency-key KEY` | none | Retries with the same key are answered once. |
| `--dev-passkey FILE` | none | For a method that needs a passkey confirmation per call (development clusters). |

A call without `--view` is `POST /apps/{app}/intents`. Both answers carry a
receipt signed by the answering node.

## file

A context's sealed files.

## proxy

```bash
meroctl [--node ALIAS|URL] proxy [--listen 127.0.0.1:2580] [--allow-remote] [--openapi FILE]
```

Serves the node's API as plain HTTP on this machine, for `curl`, scripts and
clients generated from the node API's OpenAPI document ([node API](/operate/admin-api/)): every
request is sent to the node through the same attested, sealed client every
other command uses, so it attests the node with the same `--allow-mock`,
`--tee-profiles` and `--min-release`, before it takes any request. Method, path,
query, headers and body go to the node as they came; the node's status, headers
and body come back as they come, and an event stream (`/apps/{app}/events`,
`/apps/{app}/presence/stream`) stays a stream. A refusal is the node's own
(`{ error, message, details }`), a `412 CONFIRM_REQUIRED` included: the caller
signs the challenge and sends the request again with `confirm`. On start it
prints one JSON line, `{ "listening": "http://127.0.0.1:2580", "node": URL }`,
and one line per request on stderr (method, path, status).

| Flag | Default | Meaning |
| --- | --- | --- |
| `--listen ADDR` | `127.0.0.1:2580` | Where to serve (`:0` picks a free port). A non-loopback address is refused without `--allow-remote`. |
| `--allow-remote` | off | Serve on a non-loopback address and take requests for any `Host`, with a warning: anyone who reaches the port acts as you. |
| `--openapi FILE` | none | Serve this document at `GET /openapi.json`. Without it, the node's own if it serves one, else `404` with a note. Either way `servers` is set to the proxy. |

Which credential a request carries: its own `Authorization`, passed through as
given and never refreshed; else `--api-key`; else the session `login` saved for
the node, refreshed on a `401` and saved again; else none.

What it refuses, because it holds your credential:

- a `Host` that is not `localhost` or a loopback address (DNS rebinding), unless `--allow-remote`: `403 HOST_REFUSED`;
- a request a browser sent for a web page (it carries `Origin`, or `Sec-Fetch-Site` other than `none`), since any page you open could otherwise act as you: `403 BROWSER_REFUSED`. The proxy sends no CORS headers;
- a body over 64 MiB, the sealed envelope's cap: `413 TOO_LARGE`;
- a request when the node cannot be reached, attested or understood: `502 UPSTREAM`, and nothing is sent in the clear.

It never logs a header, a query or a body. See
[Use any HTTP tool](/operate/plain-http/).

## raw

```bash
meroctl raw METHOD PATH [BODY] [--dev-passkey FILE]
```

Any API route, through the same attested, sealed client. `METHOD` is `get`,
`post`, `put` or `delete`; `BODY` is JSON (default `{}` for `post` and `put`).
Use it for what no command covers, such as `POST /auth/apikeys` with
`methods` or `allowConfirm`. With `--dev-passkey FILE` (development
clusters) it answers a `412 CONFIRM_REQUIRED` on a `post` or `delete` with
that passkey and sends the request again; without it, the `412` is printed. It
does not sign operator decisions (`428 OPERATOR_SIGNATURE_REQUIRED`): use the
`ops` command. See the [node API reference](/operate/admin-api/).

```bash
meroctl raw get /auth/me
meroctl raw post /auth/apikeys '{"label":"ci","methods":["get"],"readOnly":true}' --dev-passkey ./dev-passkey.json
meroctl raw delete /auth/aliases/notes
```

## Example session

From an empty directory to a call, then a release:

```bash
meroctl app new my-app && cd my-app
pnpm install
meroctl local dev apps/kv-store                     # cluster, build, upload, frontend on :5173
```

By hand, against the same cluster:

```bash
meroctl local up                                    # saves the node `local`, the default
meroctl login --dev-passkey ./dev-passkey.json --name ada
meroctl app pack apps/kv-store/logic --app-version 0.1.0 --out kv-store.mpk
meroctl app install --path ./kv-store.mpk
meroctl context create --package com.calimero.kv-store --name notes --alias notes
meroctl call -c notes set --args '{"key":"a","value":"1"}'
meroctl call -c notes get --args '{"key":"a"}' --view
meroctl --ops-token "$TOKEN" ops status            # the token `local up` printed
meroctl local down
```

A release:

```bash
meroctl app signer new release.key                  # once; keep it safe
meroctl app pack apps/kv-store/logic --key release.key --previous last.mpk --out release.mpk
meroctl app publish release.mpk --public            # CALIMERO_REGISTRY_API_KEY
```
