A `merod` node serves one HTTP API on its `--listen` address. The route table is
`router` in `crates/node/src/api.rs`; this page lists every route in it.
v1's separate admin API, JSON-RPC endpoint, WebSocket and SSE server are gone:
calls, reads, events and administration are all routes of this one API.

## Transport

- **In the clear:** only `GET /health` and `GET /attestation`.
- **Sealed:** everything else travels inside the sealed channel
  (`calimero-sealed`, wire format v2, Noise NK). A client fetches
  `/attestation`, checks the quote binds the node's transport key and that the
  quote's measurements match a signed mero-tee release it trusts, and only then
  seals requests to that key. The sealed envelope wraps the router from
  outside, so an opened request meets the same handlers as a direct one.
- A node started with `--dev` also accepts plain requests; a TDX node refuses
  them.
- Requests are limited to 64 MiB.

Use a client that does this: `meroctl`, `calimero-client` (Rust), mero-js
`CalimeroClient`, or calimero-client-py `CloudClient`. A hand-written `curl`
reaches only `/health` and `/attestation` on a TDX node.

## Credentials

The `Authorization: Bearer` header carries one of:

| Credential | Form | Obtained from |
| --- | --- | --- |
| Session token | `v1.<claims>.<mac>`, 15 minutes | a passkey ceremony, or `/auth/refresh` |
| API key | `cal_…` | `POST /auth/apikeys` |
| Ops token | the configured token | `--ops-token` / `--ops-token-sha256` |

Cluster peers add an `x-cluster-auth` header on `/internal/*`. See
[Authentication](/operate/auth/) for lifetimes, scopes and revocation.

The **Who** column below uses these terms:

| Who | Means |
| --- | --- |
| anyone | no credential needed |
| signed in | a session or an API key |
| session | a passkey session; an API key is refused (`403`) |
| account holder | a passkey session not bound to an app's frontend |
| installer | an account holder, or an API key scoped to no app and no method and not read-only |
| app access | whoever the app's access setting admits (`public` admits anyone); an API key's app, method and read-only scope apply |
| ops | the ops token |
| peer | another node of the cluster |

Authority beyond the credential (an org admin, the app's owner, the holder of a
governance decision) is checked when the command applies to the system log,
so every node reaches the same verdict; a refusal there answers
`400 REJECTED`.

## Errors

An error answer has an HTTP status and a JSON body:

```json
{ "status": 403, "error": "FORBIDDEN", "message": "this needs a passkey session, not an API key" }
```

with `details` when there is more to say (for example `leaderUrl` with
`421 NOT_LEADER`). The codes an operator meets most:

| Status | `error` | Means |
| --- | --- | --- |
| 400 | `BAD_REQUEST`, `BAD_NONCE`, `BAD_PACKAGE`, `BAD_BUNDLE`, `UNKNOWN_CHALLENGE`, `EXPIRED_CHALLENGE`, `TOO_FEW`, `NO_REGISTRY` | The request is malformed, refers to nothing valid, or needs a registry the node lacks. |
| 400 | `REJECTED` | The system log refused the command when it applied; `message` says why (for example the caller is not an admin of the organization). |
| 401 | `UNAUTHENTICATED` | No, unknown, expired or revoked credential. |
| 403 | `FORBIDDEN` | The credential may not do this (scope, role, governance, read-only). |
| 404 | `NOT_FOUND` | No such object, or one the caller may not see. |
| 409 | `CONFLICT` | The state does not allow it now. |
| 412 | `CONFIRM_REQUIRED` | A passkey assertion is needed; `details` carries the challenge. |
| 413 | `TOO_LARGE` | Over a size limit (a bundle over 16 MiB, a log entry over 1 MiB). |
| 421 | `NOT_LEADER` | Send it to the leader named in `details.leaderUrl`. |
| 422 | `INIT_FAILED`, `APP_ERROR`, `UPGRADE_FAILED` | The app's code refused. |
| 429 | `QUOTA_EXCEEDED`, `RATE_LIMITED` | An account quota, or a node's limit on open streams or ceremonies. |
| 503 | `UNAVAILABLE`, `NOT_CAUGHT_UP` | The cluster cannot answer now, or a replica is behind `minIndex`. |

## Public

| Route | Who | What | meroctl |
| --- | --- | --- | --- |
| `GET /health` | anyone | `{ ok, node, systemLeader, release }` | `network status` |
| `GET /attestation?nonce=HEX[&app=ID \| &appHash=HEX][&purpose=receipts]` | anyone | The node's attestation document: quote, transport key, app hash, nonce, release and profile. `purpose=receipts` attests the receipt key and the governance instead. | `attest` |

| `GET /auth/aliases` | signed in | The account's aliases | `context alias list` |

| `POST /auth/releases` | account holder | `{ version, approved, confirm? }`: approve a mero-tee release for the account's own apps (where the owner holds release approvals) | `account approve-release` |

## Packages and bundles

| Route | Who | What | meroctl |
| --- | --- | --- | --- |
| `POST /bundles` | installer | Upload raw WASM (16 MiB at most). Only with `--allow-unsigned-bundles` or `--dev`. | `app install --path X.wasm` |
| `POST /packages` | installer | Upload a signed `.mpk` | `app install --path X.mpk` |
| `POST /packages/install` | installer | `{ package, version }` from the registry | `app install P@V` |
| `GET /packages` | signed in | Installed packages, only the releases the caller may see ([who sees a release](/protocol/applications/#who-sees-a-release)) | `app list` |
| `GET /packages/{package}` | signed in | One package and the versions the caller may see; `404` when none | `app get`, `app versions`, `app get-latest-version` |
| `DELETE /packages/{package}` | account holder | Uninstall every version; refused while an app runs one | `app uninstall` |
| `DELETE /packages/{package}/{version}` | account holder | Uninstall one version | `app uninstall --version` |

Before an install is logged the node checks the publisher signature and every
artifact digest, `minRuntimeVersion`, the package's pinned signer (the first
release's wins) and that each service's WASM compiles. A node that later runs
the release fetches and verifies it again.

## Apps (contexts)

`{app}` is an app id or its context id (`hex(SHA-256(app_id))`).

| Route | Who | What | meroctl |
| --- | --- | --- | --- |
| `POST /apps` | installer | `{ name, package?, version?, service?, bundle?, org?, access?, confirmMethods?, initArgs?, metadata? }` | `context create` |
| `GET /apps[?package=P]` | signed in or anyone | Apps the caller reaches | `context list` |
| `GET /apps/{app}` | signed in or anyone | One app | `context get` |
| `DELETE /apps/{app}` | session | Delete (owner or org admin) | `context delete` |
| `POST /apps/{app}/intents` | app access | `{ method, args, idempotencyKey?, confirm? }`: a call. A confirm method answers `412` first. | `call` |
| `POST /apps/{app}/views` | app access | `{ method, args, consistency?: "stale", minIndex? }`: a read | `call --view` |
| `GET /apps/{app}/events?from=N` | app access | Server-sent events: committed events from `N`, then live ones | `context watch` |
| `POST /apps/{app}/upgrade` | account holder | `{ bundle? \| package?, version?, service?, migrate?, confirm? }`; where the owner holds app upgrades | `context update` |
| `POST /apps/{app}/access` | session | `{ access: { kind: owner \| org \| team \| accounts \| public, … } }` | `context access` |
| `POST /apps/{app}/metadata` | signed in | `{ metadata }` (owner or org admin; 16 KiB) | `context metadata` |
| `GET /apps/{app}/storage` | app access | Keys, bytes and blobs held | `context storage` |
| `GET /apps/{app}/abi` | app access | The bundle's embedded ABI | `context abi` |
| `GET /apps/{app}/attestation` | app access | Every replica's receipt-key attestation | `attest --context` |
| `GET/POST /apps/{app}/presence` | app access | Who is present; publish `{ seq, state }` | `context presence list/publish` |
| `GET /apps/{app}/presence/stream` | app access | Server-sent events: `snapshot`, then `presence` diffs | `context presence stream` |
| `POST /apps/{app}/blobs` | app access | Upload a blob | `blob upload` |
| `GET /apps/{app}/blobs` | app access | List blobs | `blob list` |
| `GET /apps/{app}/blobs/{id}` | app access | Download (id base58 or hex) | `blob download` |
| `GET /apps/{app}/blobs/{id}/info` | app access | Size | `blob info` |
| `DELETE /apps/{app}/blobs/{id}` | app access | Forget (owner or org admin) | `blob delete` |

Every `/intents` and `/views` answer carries a receipt signed by the answering
node's receipt key over `(app, index, SHA-256(JCS(result)), node)`.

## Ops

Every route needs the ops token. The Ops API returns counts, Raft status,
placement and per-app usage by id, never app state, names or credentials.

| Route | What | meroctl |
| --- | --- | --- |
| `GET /ops/status` | `{ node, system, governance, groups, nodes, apps, accounts }` | `ops status` |
| `GET /ops/metrics` | Prometheus text, including per-app usage for billing; see [Observability](/operate/observability/) and [usage metering](/operate/observability/#usage-metering) | `ops metrics` |
| `GET /ops/placement` | `{ fresh, apps: [{ app, group, replicas }], nodes: [{ id, zone, release, apps }] }`: where every app's replicas are, ids and counts only, read after a read index (`fresh`: this node caught up with the system leader); `release` is the node's attested release, `null` when unknown | `ops placement` |
| `POST /ops/nodes` | `{ id, addr, zone? }`: register a node; the system leader adds it as a learner, and promotes caught-up learners while fewer than 3 voters are left (straight to 3, never 2) | `ops add-node` |
| `DELETE /ops/nodes/{id}` | Remove a node no app keeps a replica on (system leader; elsewhere `421 NOT_LEADER`) | `ops remove-node` |
| `POST /ops/apps/{app}/replicas` | `{ replicas: [id, …] }`: move an app (at least `min(3, nodes in the cluster)` registered nodes, and only nodes on a release the app's owner approved) → `{ status, unchanged }`. The set it already has: `unchanged: true`, nothing written. Another move of the app running: `409 MOVE_IN_PROGRESS`. On a follower: `421 NOT_LEADER`. | `ops move` |
| `POST /ops/backup` | Snapshot the apps this node leads into `--backup-dir` → `{ written }` | `ops backup` |
| `GET /ops/quotas`, `POST /ops/quotas` | Read or replace the per-account quotas | `ops quotas`, `ops set-quotas` |
| `POST /ops/releases` | `{ version, approved }`, where the operator holds release approvals | `ops release` |
| `POST /ops/outbound` | `{ package, prefixes, replace }`, where the operator holds outbound approvals | `ops outbound` |
| `POST /ops/packages`, `POST /ops/packages/install`, `GET /ops/packages` | Install (upload or registry) and list the releases the operator upgrades to | `ops install`, `ops packages` |
| `DELETE /ops/packages/{package}[/{version}]` | Uninstall what the operator installed | `ops uninstall` |
| `POST /ops/apps/{app}/upgrade` | `{ bundle? \| package?, version?, service?, migrate? }`, where the operator holds app upgrades | `ops upgrade` |
| `POST /ops/orgs/{org}/upgrade` | `{ package, version, team?, cascade?, migrate? }`, an operator's upgrade run | `ops upgrade-namespace` |

Quotas (`POST /ops/quotas` replaces all of them; a field left out takes its
default):

| Field | Default |
| --- | --- |
| `maxAppsPerAccount` | `100` |
| `maxBundleBytesPerAccount` | `1073741824` (1 GiB) |
| `maxApiKeysPerAccount` | `50` |
| `maxOrgsPerAccount` | `20` |
| `maxAccounts` | `100000` |

## Internal

`/internal/raft`, `/internal/system`, `/internal/system/index`,
`/internal/call`, `/internal/view`, `/internal/blob`, `/internal/blob/get`,
`/internal/blob/held`, `/internal/blob/delete`, `/internal/storage`,
`/internal/presence`, `/internal/app-ready` and `/internal/events` are for the
cluster's own nodes: they need the cluster secret (an HMAC of the cluster key
and the cluster name) inside a sealed channel whose key was attested like any
client's. Nothing outside the cluster calls them.

`/internal/cluster-key` is the one internal route without the cluster secret:
a new node, often of the next mero-tee release, asks it for the cluster key
K_c (`{ cluster, node, token }`). It is never answered with the key: the peer
delivers K_c to the address the cluster has for that node id, inside a sealed
channel to the key the TD there attests (`403` for another cluster, an
unknown or removed node, or a delivery that fails; `429 BUSY` past four at
once). See [The cluster key](/protocol/encryption/#the-cluster-key-k_c).

<Aside type="note" title="App frontends">
  With `--apps-domain`, requests whose `Host` is `{label}.{domain}` are served
  before any of these routes: `GET`/`HEAD` of a package's frontend files and
  `/.well-known/calimero.json`. See [Networking](/operate/networking/#app-frontends).
</Aside>
