The claim Calimero makes is narrow and checkable: **nobody operating the
cluster — Calimero included — can read an app's data or put new code in front
of it without the party the deployment named for that decision.** This page
lists what that rests on.

## What is trusted

| Trusted | For | Checked by |
| --- | --- | --- |
| Intel TDX and its attestation (DCAP collateral) | That a quote comes from a genuine TD with the measured image, and that a debug TD is not passed off as one | Every client and peer, on every new channel |
| The signed mero-tee release | That the measurements in `published-mrtds.json` are the image Calimero built and signed (Sigstore) | `Measurements::Release` in the client and peer policy |
| mero-kms | Releasing the storage key only to an attested TD | The KMS client verifies the KMS against the signed release too, and the node reports the KMS quote it accepted, bound into its own quote (`purpose=kms`, [Attestation](/protocol/tee-attestation/#which-kms-a-node-took-its-keys-from)), so anyone verifying the node can check which KMS that was |
| The `merod` build in that image | Everything in this reference | Its measurement is part of the image |
| The person's authenticator | Their passkey | WebAuthn, with user verification for step-ups |

Not trusted: the host and hypervisor, the disks, the network and any TLS
terminator, the operator, other tenants, the app's publisher beyond its own
code, and app code beyond what its owner approved.

## Who can do what

| Party | Can | Cannot |
| --- | --- | --- |
| **Network / proxy** | See that clients talk to nodes, sizes, timing; drop or delay traffic | Read or forge requests, responses or frames; replay a request; impersonate a node without its attested key |
| **Host / hypervisor** | Stop, freeze, restart a node; read sealed disks; withhold the network | Read memory of a non-debug TD; open sealed values without K_c; get K_r (it comes from mero-kms, not the host) or K_c (wrapped under K_r, or delivered by a peer only to the attested TD at a registered node's address) |
| **Operator** (ops token) | Register nodes, move replicas onto approved releases, set quotas, take sealed backups, read counts and Raft status; and whatever governance gives it | Read state, events, blobs or credentials; sign in as anyone; move an app's data to an unapproved image; upgrade apps, approve releases or outbound destinations unless governance gives it that decision |
| **A node of the cluster** | Everything this reference describes | — (it is the trusted computing base; that is why every peer is attested) |
| **An app's owner** | Upgrade it, change its access, approve releases and outbound prefixes for it (where governance says owner), delete it | Read other apps; act for other accounts |
| **A member** | What the app's access rule and the app's own code allow | Read another member's private space; forge a writer rotation, a blob mark or TEE-only state; write if their team row is read-only |
| **An app's frontend** (third-party page) | Act as the signed-in person for that package's apps only | Reach other apps, manage credentials or API keys, approve anything, upgrade or uninstall |
| **An API key** | What its scope allows | Manage credentials or keys; produce a passkey assertion |

## Which mechanism stops which attack

- **Reading traffic** — the sealed channel, keyed to an attested key, with
  forward secrecy per session ([Networking](/protocol/networking/)).
- **A fake or outdated node** — the quote check with a measurement policy and a
  release floor, for clients and peers alike ([Attestation](/protocol/tee-attestation/)).
- **Reading disks** — AES-256-GCM under K_c, bound to row, group and column;
  hidden row keys ([Encryption](/protocol/encryption/)).
- **A new image reaching data** — release approvals, enforced by the replicas
  that hold the data before any Raft entry or snapshot leaves
  ([Deployment governance](/protocol/governance/#release-approvals)).
- **New code reaching data** — app upgrades held by one named party, with a
  passkey step-up for owners.
- **Exfiltration over the network** — outbound HTTPS only to hosts the operator
  allows, under prefixes the app's signed manifest declares and its approver
  approved, from writing runs only.
- **A stolen session** — 15-minute tokens, single-use refresh tokens whose reuse
  revokes the session, revocation that holds on every node before the next
  request.
- **A lagging replica granting stale access** — credentials and access judged
  on fresh system state (a read index).
- **Forged authority in the log** — commands built only by nodes from verified
  credentials, and authority checked again at apply.
- **A malicious app frontend** — its own origin and a package-bound session.
- **A malicious app** — the WASM sandbox and its limits; the host's key space
  is closed to it; it reaches only its own blobs and its caller's private space;
  xcalls only into entry points within its organization.
- **Proving all this to a user** — `verify_app_cluster`: every replica's quote,
  receipt keys, and the governance they all attest; receipts on every answer.

## What is not protected yet

- **Rollback.** A host that restarts a node on an older copy of its disk is not
  detected. A rollback counter (a mero-kms epoch, restored nodes rejoining as
  learners) is proposed, not done.
- **Keys per app.** One K_c covers every app on a cluster; keys per app from
  mero-kms are not done.
- **Availability.** The host and operator can stop nodes. Raft tolerates the
  loss of a minority of an app's replicas. A new app's replicas are spread
  across the zones the operator registered ([placement](/protocol/context-lifecycle/#create));
  moving existing apps between zones is the operator's (`ops placement`, `ops move`).
- **Event audiences.** Everyone who reaches an app receives all its events.
- **Side channels** on the TD and timing of requests are outside this model.
- **A debug image.** A debug TD exposes its memory to the host. Clients refuse
  debug profiles unless told otherwise, and nodes trust debug peers only when
  they are debug themselves; a cluster on a debug image protects nothing.
