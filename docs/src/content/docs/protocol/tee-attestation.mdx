Every node runs inside an Intel TDX VM built from a signed **mero-tee
release**. Before a client or another node sends it anything, it asks the node
for a **quote** — a hardware-signed statement of what the VM is running — and
checks it. The check lives in one place, `calimero_client::attest`,
shared by the Rust client, `meroctl`, calimero-client-py and every node judging
its peers; mero-js's `src/cloud-v2/attestation.ts` implements the same check.

## The attestation document

`GET /attestation?nonce=<32 bytes hex>[&app=<app>|&appHash=<hex>][&purpose=receipts]`
answers, unsealed:

| Field | Meaning |
| --- | --- |
| `quote` | The TDX quote, base64 (a mock quote on `--dev` nodes) |
| `transportKey` | The node's X25519 transport key, hex |
| `appHash` | A bundle hash bound into the quote (zeros when none was asked) |
| `nonce` | The caller's nonce, echoed |
| `release` | `{ version, profile }`: the mero-tee release and image profile the node says it runs |
| `cluster`, `node`, `mock` | The cluster name, node id, and whether the quote is a mock |
| `receiptKey`, `governance` | With `purpose=receipts` only: the node's receipt key and the cluster's governance |

The quote's 64 bytes of report data bind the request to the key:

```text
transport:  report_data = nonce ‖ SHA-256("calimero.tee-attest.transport-key.v1" ‖ app_hash ‖ transport_key)
receipts:   report_data = nonce ‖ SHA-256("calimero.tee-attest.receipt-key.v2" ‖ receipt_key ‖ SHA-256(governance JSON))
```

The nonce makes the quote fresh: an old quote cannot be replayed. The second
half commits the quote to a key that lives only in that VM's memory. A caller
that verifies the quote therefore knows the key belongs to a process running
the measured image, and nobody else can open what is sealed to it.

## What the verifier checks

`attest::verify` (transport) and `verify_receipt_key` (receipts) run the same
steps (`verify_report`):

1. **Mock quotes** are accepted only when the policy says `allowMock` (a
   development cluster), and then only their report data is checked.
2. **A measurement policy is required** for a real quote. `Measurements::None`,
   the default, refuses every real quote. `Pinned` checks fixed MRTD/RTMR
   allowlists. `Release` reads the release the node names, refuses it if it is
   older than the floor (`min_version`, else `DEFAULT_MIN_RELEASE` = `2.3.109`),
   fetches that release's `published-mrtds.json` and verifies its Sigstore
   signature (`calimero-tee-release`), and requires the quote's MRTD and RTMRs
   to match one of the allowed profiles. Debug profiles are dropped from the
   allowed list unless the caller asked for them: a debug TD lets the host read
   its memory.
3. **The quote is genuine**: DCAP verification against Intel's collateral
   (`calimero-tee-attestation`), the TD is not a debug TD, and the report data
   is exactly the expected 64 bytes.
4. **Policy**: the TCB status is allowed (`UpToDate` unless the caller allows
   more), and the measurements match the profile found in step 2.

Only then does the client open a [sealed session](/protocol/networking/#the-sealed-channel)
to the transport key.

## Peers are judged the same way

A node opening a channel to a peer uses the same check with its own policy:
`Release` with `--peer-profiles` (default: its own `MERO_TEE_PROFILE`) and
`--peer-min-release`. A node trusts debug-profile peers only when it runs a
debug image itself. What the peer's verified attestation named as its release
is remembered and decides whether the peer may receive an app's data
([release approvals](/protocol/governance/#release-approvals)).

:::note[v1 comparison]
v1 used attestation to admit "fleet" nodes into a namespace as read-only TEE
replicas or relays, with an admission handshake, a measurement allowlist set by
the namespace's admins, and self-purge on eviction. Here every node is a TEE,
and attestation is the precondition for any conversation, with a client or a
peer. There is no admission role: a node that passes the check is a peer; one
that fails is never sent a byte.
:::

## Receipts

Every successful `/intents` and `/views` answer carries a **receipt**: the
answering node's signed statement that entry `index` of app `app` produced this
result.

```text
Receipt { app, index, resultHash, node, key, signature }
resultHash = hex(SHA-256(JCS(result)))                      // RFC 8785 canonical JSON
signature  = Ed25519(receipt_key,
               "calimero.receipt.v1\0" ‖ app ‖ 0 ‖ index (u64 BE) ‖ resultHash ‖ 0 ‖ node (u64 BE))
```

The receipt key is an Ed25519 key each node makes in memory at start and never
stores. It is attested on its own (`purpose=receipts`), together with the
cluster's governance. So a receipt is checkable later, offline, by anyone who
holds that node's receipt-key attestation: it shows that a genuine node of a
cluster deployed under those rules returned that answer.

## Verifying the whole app cluster

`GET /apps/{app}/attestation?nonce=` asks every replica of the app for its
receipt-key attestation over the caller's nonce and returns them together.
`Client::verify_app_cluster` checks each one with the client's policy, checks
each replica answers as the node it is listed as, and requires every replica to
attest the **same governance**. It answers the attested receipt key per node
and that governance. A replica that does not answer, or does not pass, fails
the whole check.

What a user learns from it:

- every node that holds the app's data is a genuine TD on an image they trust;
- which keys sign the app's receipts (a receipt from any other key is not one
  to trust);
- who may move the app to new code, approve images, and approve outbound
  destinations ([Deployment governance](/protocol/governance/)).

The entry node gathers the documents but cannot forge them: each quote binds
the caller's fresh nonce and is verified against Intel's collateral.

## Generating quotes

A TDX node produces quotes through the kernel's TSM configfs interface
(`calimero_tee_attestation::generate_attestation`). A `--dev` node (and
`merod local`) produces mock quotes with the same report-data layout, which a client
accepts only with `allowMock`; `meroctl node add … --allow-mock` keeps that
permission for one saved node only. A node without `--dev` always produces
real quotes and refuses mock quotes from its peers.
