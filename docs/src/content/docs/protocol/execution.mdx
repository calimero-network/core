An **application** is a WASM module that defines a state machine: its data
types and the methods that change them. An **execution** (a *run*) is one call
of one method. On a cluster, only the app group's **leader** runs calls; the
other replicas apply what the run produced ([Replication](/protocol/replication/)).

An app runs on one of two runtimes, decided once from the WASM its bundle names
(`AppRecord::executor`): a core module built with `calimero-sdk` runs on
`calimero-runtime` (wasmer); a
`calimero:app` component built with `calimero-app-sdk` runs on
`calimero-app-engine-wasmtime` through the host core `calimero-app-host`. For a
core module the node calls `Module::run_cloud` (`crates/node/src/app.rs`,
`Executor`), compiling each bundle once and caching the module by its hash;
components go through `crates/node/src/component.rs`.

The run reads the app's applied state through a copy-on-write **overlay**
(`Overlay`): a read checks the run's own writes first, then the state; a write
or delete stays in the overlay. Nothing touches the app's state during the run.
When it ends, the overlay's writes, in the order they last happened, become the
outcome's **diff**. If the run trapped or the app returned an error, the diff is
empty.

The guest commits its storage changes through the SDK,
and the runtime returns the commit **artifact** (a borsh `StorageDelta`).
The node does not replicate the artifact: it reads it only to list the storage
entities the run touched, which is what [search](/protocol/reads/#search)
re-indexes.

## The host ABI boundary

The guest and the host share a block of linear memory and a set of numbered
registers. Arguments cross as `(pointer, length)` descriptors; the host
bounds-checks every access and hands larger results back through registers.
Exported methods take no arguments and return nothing: input arrives through
`input()`, the result leaves through `value_return`.

## What the host offers a cloud run

| Family | What it does on a cluster |
| --- | --- |
| `context_id`, `account_id`, `executor_id`, `device_id` | The app's context id (`SHA-256(app_id)`), and the caller's account. `executor_id` is the account too: there are no per-device keys ([Who a run acts as](/protocol/authorship/)) |
| `caller_org` | The caller's role and teams in the app's organization, or nothing |
| `input`, `value_return`, `log_utf8`, `emit`, `emit_with_handler` | Arguments in; result, logs and events out. An event may name a handler to run after the entry commits ([Event handlers](/protocol/xcall/)) |
| `storage_read` / `storage_write` / `storage_remove` | The app's replicated state, through the overlay |
| `private_storage_*` | The caller's own space in the app's state (below) |
| `storage_index_*` | The ordered index. The node keeps none: index writes report "not persisted", and the SDK falls back to its unindexed path |
| `time_now`, `random_bytes` | The leader's wall clock and randomness, read once: followers apply the result |
| `xcall`, `xcall_origin` | Queue a call into another app; read which app called this one |
| `blob_*` | The cluster's [blob store](/protocol/blobs/), for the app's own blobs |
| `search_query` | The app's own full-text indexes, in views only |
| Sealing functions (`tee_sealing_key`, …) | `TeeOnly` / `TeeSecret` state, with keys the node derives per app |
| `http_request` | One outbound HTTPS request, under the gates below |
| `ed25519_verify` | Signature checks inside app logic |

## Three storage spaces in one state

| Space | Where it lives | Who reads it |
| --- | --- | --- |
| **Shared** | The app's state, keys as the app writes them | Every run |
| **Private** (`env::private_storage_*`) | The app's state, under `\0calimero.private\0 ‖ account ‖ 0` | Only runs whose caller is that account |
| **Host** (`\0calimero.*`) | The app's state: private spaces, shared-cell writer sets, blob marks | Only the node |

The caller's private space is part of the app's
replicated state, sealed on disk like the rest, and the host hands a run only
its caller's space: app code cannot address another account's.

The host's key space is reserved. App code's overlay answers nothing under
`\0calimero.` and a run that reads or writes there is refused outright
(`the run addressed the host's key space`), so an app can neither forge a
writer set or a blob mark nor read someone's private space by raw key. The node
writes there itself (`Overlay::set_host`) as part of the same entry.

## What the node checks after the run

Before a run's outcome becomes an entry, the node applies these host-side
rules:

- **Shared-cell writer rotations** (`SharedStorage`): each rotation must step
  from the set in effect (the state's, or at genesis the prior set the cell id
  commits to), and the run's account must hold `ADMIN` in it. A TEE run, an
  app's own run (handler or xcall) or a public call may not rotate. The new set
  is written beside the cell, in the same entry.
- **Blobs the run wrote** are kept by the leader, marked as the app's in the
  diff, and spread to the other nodes after the entry commits.
- **Read-only team members**: a member whose row in the app's team is read-only
  reaches a component app's views only: a call to any other method is refused with
  `403` before it runs. On a wasmer app the call still runs, but if it would write
  anything (a diff or a blob) the node answers `403` instead of appending it.

## Outbound HTTPS

`http_request` (`calimero-outbound`) makes one request per run, and only when
every gate holds:

1. the operator turned outbound on and allows the host (`[outbound]` in the
   node's configuration);
2. the app's bundle is a signed release whose manifest declares a URL prefix
   covering the request;
3. that prefix was approved for the publisher by whoever the cluster's
   [governance](/protocol/governance/) gives outbound approvals;
4. the run writes: a call, a follow-up or a timer, never a view, `init`, a
   migration, or a read-only member's call;
5. `https` on port 443 to a name that resolves only to public addresses, within
   the size limits, no redirects.

The request is made while the leader holds the group's propose lock, on its own
thread. A run repeated after a leader race sends it again.

## Determinism is not what converges

Only the leader runs, so `time_now`, `random_bytes`, outbound responses and search
answers cannot make replicas disagree. Runs are still bounded and
transactional: resources are capped ([Limits](/protocol/limits/#execution-limits)),
and a trap or an app error leaves an empty diff.

## Views and migrations

A **view** runs the same way against a replica's applied state, with search
available, and its writes are discarded ([Reads](/protocol/reads/)). A
**migration** runs the target bundle's `#[app::migrate]` export over the old
state, writes the returned root state and checks it with the app's
`__calimero_migration_check` ([Upgrades](/protocol/upgrades/)).
