This page orients you in the release-v2 workspace: the two binaries, what is
inside a node, and the path a call takes. The full crate list is in the
[crate guide](/contribute/crate-guide/); each crate's `AGENTS.md` has the detail.

## Two binaries over libraries

| Binary | Crate | Is |
| --- | --- | --- |
| `merod` | `crates/merod` | A thin command line: it turns flags, `MEROD_*` variables and `config.toml` (`node_config::NodeArgs`) into `calimero_node::Config` and calls `calimero_node::run`. Also `local`, `inspect` and `kms disk-key`. |
| `meroctl` | `crates/meroctl` | v1's command tree over `calimero-client`: every request is attested and sealed. |

Everything a node does is in `calimero-node` (`crates/node`).
v1's actor-based node (`NodeManager`, `ContextManager`, `NetworkManager`, the
sync manager, gossip, the DAG) is deleted.

## Inside a node

| Part | Where | Does |
| --- | --- | --- |
| Log engine | `calimero-log` | Multi-group Raft (openraft) over one sealed RocksDB per node: logs, votes, state, blobs and snapshots. |
| System group | `node/src/system.rs` (group 1) | The fleet, app directory, packages and bundle hashes, accounts, passkeys, API keys, refresh tokens, session keys, organizations, teams, invites, quotas, governance. Commands carry their actor and are authorized in `apply`, so the log decides. Kept in memory, checkpointed with snapshots. |
| App groups | `node/src/app.rs` | One Raft group per app instance on its replicas. State lives on disk as hidden rows of the group; only a small head is in memory. |
| Executor | `app::Executor` over `calimero-runtime` | Runs a call's WASM on the leader against a copy-on-write overlay and returns `{ result, diff, events }`. |
| Node | `node/src/node.rs` | Routing to leaders, placement, reconciling hosted groups with the directory, follow-ups (event handlers, xcalls, timers), blob replication, backups. |
| API | `node/src/api.rs` | The HTTP routes (`router`): `/auth`, `/packages`, `/bundles`, `/apps`, `/orgs`, `/invites`, `/ops`, `/internal`. |
| Sealed transport | `calimero-sealed` | Wraps the router from outside; opens sealed requests and routes them afresh. |
| Identity | `calimero-identity` | WebAuthn verification, session tokens, API keys, confirm challenges. |
| Attestation | `calimero-tee-attestation`, `calimero-client::attest`, `calimero-tee-release` | Quote generation, and the one verification clients and peers share. |
| Packages | `node/src/packages.rs`, `calimero-bundle`, `calimero-app-downloader` | Signed `.mpk` verification and registry fetches. |
| Outbound | `calimero-outbound` | The gated HTTPS client a run may use. |
| Search, presence, frontends | `services.rs`, `presence.rs`, `app_host.rs`, `calimero-search` | Derived in-memory search indexes, ephemeral presence, app frontends on their own origins. |
| Storage key | `node/src/kms.rs`, `calimero-kms-client` | K_r from mero-kms. |

- **Calls are linearized per app.** The leader serializes proposals, so a diff
  always applies to the state it was built on (`base_index`); one built on
  replaced state applies as a no-op and the call is re-run.
- **Reads.** A view goes to the leader (strong) or, with `minIndex`, to any
  replica that has applied that far.
- **Follow-ups** queued by an entry (event handlers, xcalls, timer ticks) run
  once, on the leader, as entries of their own.
- **Bundles and blobs** are not in the log: they are stored in every node's
  sealed blob store (a majority before the answer) and the log records their
  hash. Log entries are capped at 1 MiB.
- **System writes** (sign-up, installs, org changes) go to the system leader
  the same way; authority is checked when they apply.

## What is still v1

The SDK (`calimero-sdk`, `calimero-storage`, `calimero-sys`,
`calimero-wasm-abi`) and the WASM runtime (`calimero-runtime`) are the same
ones v1 apps were built against, so every v1 app deploys unchanged. The runtime
still links a few v1 node crates: `calimero-node-primitives` (which brings
`calimero-governance-types`, `calimero-network-primitives`,
`calimero-blobstore` and `calimero-utils-actix`), `calimero-context-config`,
`calimero-store` and `calimero-crypto`. They stay only for that, and the crate
guide marks them.
