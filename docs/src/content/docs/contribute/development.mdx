The practical loop: build, run a cluster, test, and the conventions a PR has to
meet.

## Prerequisites

- **Linux.** `merod` and the node's tests need Linux (x86_64 or aarch64). On
  macOS, run the node in Docker ([Install](/operate/install/#first-run-on-macos-a-node-in-docker))
  and build `meroctl` natively; run the node's test suites in a Linux
  container or VM.
- **Rust** pinned by `rust-toolchain.toml` (`1.98.0`, with `clippy` and
  `rustfmt`), and the WASM target:

  ```bash
  rustup target add wasm32-unknown-unknown
  ```

- **System packages:** `clang`, `libclang-dev`, `make`, `pkg-config`,
  `libssl-dev`.
- **cargo mero**, to build apps with their embedded ABI:

  ```bash
  PATH="$(scripts/setup-cargo-mero.sh):$PATH"
  ```

## Build

```bash
cargo build -p merod -p meroctl          # the two binaries
cargo check --workspace                  # everything
cargo mero build --manifest-path apps/kv-store/Cargo.toml   # one app, with its ABI
./scripts/build-all-apps.sh              # every app in apps/
```

The node reads timers, handlers, xcall entry points, migrations and search
exports from the bundle's embedded ABI, so build apps the node will run with
`cargo mero build`; a plain `cargo build --target wasm32-unknown-unknown`
bundle runs, but without those.

## Run local nodes

The quickest cluster is one process:

```bash
cargo run -p merod -- local            # 3 nodes on 127.0.0.1:2501-2503, state in .merod-local/
cargo run -p merod -- local --fresh    # start over
```

then, in another terminal:

```bash
cargo run -p meroctl -- node add local http://127.0.0.1:2501/ --allow-mock
cargo run -p meroctl -- login --dev-passkey ./dev-passkey.json --name dev
cargo run -p meroctl -- app install --path target/wasm32-unknown-unknown/app-release/kv_store.wasm
```

`merod local` runs every node in one process, with mock attestation and the
development storage key. To exercise separate processes (crashes, restarts,
a frozen node), run each node yourself:

<Steps>

1. Initialize three nodes under a scratch home:

   ```bash
   export CALIMERO_HOME=$PWD/.nodes
   P=1=http://127.0.0.1:2601/,2=http://127.0.0.1:2602/,3=http://127.0.0.1:2603/
   for i in 1 2 3; do
     merod --node n$i init --dev --node-id $i --listen 127.0.0.1:260$i \
       --public-url http://127.0.0.1:260$i/ --peers $P --ops-token devtoken
   done
   merod --node n1 config --bootstrap
   ```

2. Run each in its own terminal:

   ```bash
   merod --node n1 run
   merod --node n2 run
   merod --node n3 run
   ```

3. Point `meroctl` at any of them with `--allow-mock`.

</Steps>

All three share the default `--cluster dev`, so they derive the same
development storage key. Add `--origins` for a browser frontend on another
port, and `--registry-url` to install `PACKAGE@VERSION`.

<Aside type="note">
  A node's configuration and data live under `$CALIMERO_HOME/<node>/`
  (default `~/.calimero/<node>/`), outside the repository. `meroctl` keeps its
  saved nodes and sessions under `$CALIMERO_HOME/meroctl/`.
</Aside>

## Logs

```bash
RUST_LOG=debug merod --node n1 run
RUST_LOG=info,calimero_node=debug,openraft=info merod --node n1 run
```

`run` defaults to `info,openraft=warn`, `local` to `warn,openraft=off`. Keep
account ids and user or app content out of `info!` and above:
`scripts/check-no-user-data-at-info.py` fails a change that logs them.

## Before a PR

Run these locally; they are what the required checks are built from:

```bash
cargo fmt --check
cargo clippy --workspace --all-targets --features calimero-storage/testing -- -D warnings
cargo clippy -p calimero-tee-attestation -p calimero-node --all-targets \
  --features calimero-tee-attestation/mock-attestation,calimero-node/outbound-testing -- -D warnings
```

then the tests for what you changed ([Testing](/contribute/testing/) has the
fixtures they need), for example:

```bash
cargo test -p calimero-node
cargo test -p merod -p meroctl
```

`./scripts/check-like-ci.py` runs every job the required `Rust` check waits
on, read from `.github/workflows/ci-checks.yml` (`--list` shows them,
`--only <name>` runs some). Always run clippy with `-D warnings`:
`-A warnings` allows every lint and can only pass.

<Aside type="note">
  A pre-commit hook runs `cargo fmt --check` on staged Rust files. It installs
  itself during any `cargo build` or `cargo test` through the
  `calimero-git-hooks` build script, works from linked worktrees, and lives in
  `.githooks/`. If `git config --get core.hooksPath` prints `.husky`, clear it
  once with `git config --unset core.hooksPath`.
</Aside>

## Commit and PR conventions

Commit subjects and PR titles follow the
[commit rule](https://github.com/calimero-network/core/blob/master/CODING_STANDARDS.md#commits)
in the coding standards. For pull requests:

- A PR focuses on functionality or style, not both.
- The PR template's **Description**, **Test plan** and **Documentation update**
  sections are filled in, and its Trust boundary block where a trust-boundary
  path is touched.
- A bug fix shows its reproduction and before and after output; the
  reproducing test stays as the regression test.
- Maintainers squash-and-merge; resolve each review conversation as you address
  it.

The rest of the Definition of Done is in the root
[`AGENTS.md`](https://github.com/calimero-network/core/blob/master/AGENTS.md#definition-of-done).
