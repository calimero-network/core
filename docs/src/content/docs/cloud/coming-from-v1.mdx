Calimero 1.0 replaced the earlier peer-to-peer, node-per-user design (v1)
with a cluster of attested TDX nodes, one Raft log per app instance and one for
the cluster. Apps built with the Rust SDK (`calimero-sdk`, SDK 0.12) keep
running unchanged on the same wasmer runtime. Everything else a v1 user
touched — the node, the APIs, the CLI tree, how replicas agree — changed. This
page is the one place the docs talk about v1; every other page describes only
the current system.

## Names

The command line kept v1's command names, so the names below still appear in
`meroctl` and in a few API fields.

| v1 name | Calimero 1.0 | `meroctl` |
| --- | --- | --- |
| Application | A signed package (`.mpk`), installed once per cluster | `app` |
| Context | An app instance; its context id is `hex(SHA-256(app_id))` | `context` |
| Namespace | An organization | `namespace` (`ns`) |
| Group / subgroup | A team of an organization, nested, open or restricted | `group` |
| Identity, device keys | An account; each passkey is one of its devices | `account` |
| Cross-context call | An xcall into another app's `#[app::xcall]` entry point | |
| Cascade group upgrade | An organization upgrade run | `group upgrade` |

## Removed, and what replaced it

| Removed | Replacement |
| --- | --- |
| A node per user (`merod` on your machine), joined by invitation | A cluster of attested TDX nodes run by Calimero or by you; people have accounts, not nodes ([Concepts](/protocol/concepts/)) |
| merobox as a way to run nodes | `merod local` for a development cluster; merobox remains a test harness ([Testing](/contribute/testing/)) |
| Calimero Desktop | A browser and the clients (mero-js, calimero-client-py, `calimero-client`, `meroctl`); a package's frontend is served by the cluster ([Packages & frontends](/protocol/applications/#frontends)) |
| Scopes, the signed op-log and its causal DAG, scope roots | One Raft log per app and one for the cluster ([Replication](/protocol/replication/)) |
| Gossip broadcast of each signed delta (libp2p gossipsub, DHT, point-to-point streams) | Raft `AppendEntries` from the leader over attested, sealed peer channels; peers are listed in the system group ([Networking](/protocol/networking/)) |
| The receive path: verify, authorize at the causal cut, decrypt, buffer, fold | Followers apply the committed diff in index order; nobody re-executes |
| Sync handshakes, verdicts, HashComparison / LevelWise transfer, divergence detection, partition recovery | Missing entries, or a snapshot when they were compacted; a minority cannot commit, so replicas never diverge |
| Hybrid logical clock ordering across nodes | The log index orders calls; storage timestamps are internal to the format ([CRDT collections](/protocol/crdt-internals/)) |
| Merge-on-receive through the app's own merge code (`__calimero_sync_next`) | The leader runs each call against the state the previous one left |
| Governance operations judged at the author's causal cut | System commands checked when they apply ([The system group](/protocol/system-group/)) |
| Scope keys delivered by ECDH, rotated on every removal | One storage key per cluster from mero-kms; access is checked per request, so a removal needs no rotation ([Encryption](/protocol/encryption/)) |
| Each node's own at-rest key and per-kind column families | One sealed store of Raft groups per node ([Storage schema](/protocol/storage/)) |
| Account roots, per-device keys, device certificates, pairing, root backup | Accounts with passkeys; recovery is what the authenticators provide ([Identities](/protocol/identities/)) |
| Four write paths: own node, relay under a warrant, TEE relay, TEE authority | One path: any node, sealed ([The write path](/protocol/write-path/)) |
| Delegated authorship and warrants | The node runs each call for the caller it authenticated, and the entry records the caller ([Who a run acts as](/protocol/authorship/)) |
| Direct admission through an admitter | Invite tokens ([Organizations](/protocol/organizations/#invites)) |
| TEE "fleet" nodes admitted into a namespace (`ReadOnlyTee`, `RelayTee`), measurement allowlists set by admins, self-purge | Every node is a TEE and is attested before any conversation; the cluster is every app's TEE ([Attestation](/protocol/tee-attestation/)) |
| Private storage kept on the member's own node, never synced | The caller's own space in the app's state, replicated and sealed, handed only to that caller's runs |
| A member's TEE share sealed to each device | Sealed to a per-member key the node derives |
| Read-only members' writes discarded silently | Refused with `403` |
| Three kinds of leave, delete-with-history, tombstone collection | Losing access is a system command; deleting an instance removes it from every replica |
| Blob announcements, DHT records, peer blob transfer | One blob store per cluster; an app's blobs are those its state marks ([Blobs](/protocol/blobs/)) |
| Lazy per-node migrations on first read | A migration runs once, on the leader, and its result is replicated ([Upgrades](/protocol/upgrades/)) |
| `mero-auth`, its JWT providers, embedded and proxy modes, `POST /admin/client-key` | Passkeys, sessions, refresh tokens and scoped API keys in the system group ([Authentication](/operate/auth/)) |
| The admin API (`/admin-api/*`), JSON-RPC endpoint, WebSocket and SSE servers | One node API, sealed; events are server-sent events inside the envelope ([Node API](/operate/admin-api/)) |
| `merodb` | `merod inspect` |
| The operator's own node and its admin API that could read everything | The Ops API: counts and Raft status, no read path into apps ([The operator](/protocol/operator/)) |

## Edge cases of v1's governance

| v1 rule | Now |
| --- | --- |
| Inheritance walked the scope tree at the author's causal cut | `Org::in_team` walks the parent chain on the applied state |
| Last-admin protection, owner immunity | The owner cannot be removed; ownership moves only by the owner's own command |
| Self-leave versus admin removal (key rotation owed) | No keys to rotate; a manager's removal also sticks against inheritance |
| Concurrent governance ops at the same parents | The log orders them; each applies to the state the previous one left |
| Per-signer nonce windows against replay | Commands are proposed by nodes from authenticated requests; there is nothing to replay |
| Cascade delete of a subgroup | `DeleteTeam` takes the subtree and its apps |
| The deny-list | Withholding `JOIN_OPEN_TEAMS` keeps a member out of open teams |

## meroctl commands with no counterpart

`context sync` and `group sync` (Raft replicates), `context identity`,
`account pair-*`, `seal-to` and `device-init` (a passkey is the device),
`peers` (there is no gossip network) and `tee fleet-join` (use `ops add-node`).
Everything else is in the [meroctl reference](/operate/meroctl/).

## Terms with no counterpart

Scope, scope root, op-log, operation id, causal DAG, head, causal cut,
authorization at the cut, projection, fold, stamp, generation (of a DAG),
gossip, topic, broadcast, stream, heartbeat (of DAG heads), sync, verdict,
divergence, reconciliation, absorb buffer, scope key, key delivery, key
rotation on removal, warrant, delegation, executor/relay, admitter, fleet node,
`ReadOnlyTee`, `RelayTee`, self-purge, stale-schema fence.

## Metrics

Series that measure the same thing as v1's keep v1's names and labels
(`http_requests_total`, `http_request_duration_seconds`, `merod_build_info`,
`process_*`, `storage_disk_usage_bytes`), so dashboards built for v1 keep
working on them; `merod_build_info`'s `peer_id` label now carries the node id,
and the old `blobstore` series is part of `datastore`. v1's sync, gossip, DAG,
governance and network-channel metrics have no counterpart
([Observability](/operate/observability/)).

## Crates removed

`merod` and `meroctl` internals, `mero-auth` (`crates/auth`), `authz`,
`client`, `config`, `context` (except `context/config`), `dag`,
`governance-store`, `network` (except `primitives`), `node` (except
`primitives`), `op`, `op-adapter`, `projection`, `server` (with its
primitives), `store/encryption` and `merodb`. Today's `crates/client` and
`crates/node` are new crates under those names. The few old crates the wasmer
runtime still links are listed in the [crate guide](/contribute/crate-guide/).

## Moving an app

- **Rust SDK apps** build and deploy as they are: same SDK, same runtime. Build
  with `cargo mero build` so the bundle embeds its ABI (handlers, xcall entry
  points, timers and migrations are read from it), and ship a signed `.mpk`.
- **Identity.** There are no device ids: `env::account_id()` and
  `env::executor_id()` are both the caller's account.
- **Ordering.** Calls on one instance are linearized, so code that relied on
  merging concurrent writes still works, and plain values work too.
- **Frontends.** Sign in with passkeys through mero-js; there is no local node
  to talk to. See [Writing apps](/cloud/apps/).
