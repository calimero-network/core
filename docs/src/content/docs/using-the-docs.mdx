## How each track is grouped

Every track separates learning-oriented pages from reference:

| Group | What it is | How to read it |
| --- | --- | --- |
| **Get started** | A tutorial path | In order, top to bottom |
| **Guides / How-to** | Task-focused recipes | Jump to the one you need |
| **Reference** | Exhaustive look-up | Search / scan, don't read cover to cover |
| **Deep dives** | Implementation internals | When you want the "why" and the sharp edges |

The Protocol Reference groups its pages differently (_The model_, _The call
path_, _Trust_, _People &amp; authority_, _Apps_, _Reference_) because it is a
sequence: it follows one call from a client's sealed request to a committed
log entry, then widens out.

## Page conventions

- **Callouts.** `:::note` is context, `:::tip` is a shortcut, `:::caution` is a
  footgun. In the Protocol Reference, a _v1 comparison_ note says what a
  mechanism replaced and why.
- **Diagrams** are animated — hit **▶ Replay** to step through a flow again.
- **Code blocks** have a copy button; where a format matters (report data,
  receipts, key layouts) the page gives it exactly.
- **Release candidate.** Everything here is meant to match current code, which
  may still change; request and entry formats are not yet versioned. What is
  not done yet is named where it matters.
