## Why Calimero

Customers want control of their data, which today means self-hosting: servers, patching, secrets, on-call and a separate enterprise edition.
Calimero gives them the control without the hosting.

<CardGrid>
  <Card title="One signed bundle" icon="seti:wasm">
    App logic and its frontend ship as one signed package, and the same build
    runs on every node. [Package and sign →](/build/packaging-signing/)
  </Card>
  <Card title="State that syncs itself" icon="random">
    Nodes replicate state as signed operations that converge with CRDTs. No
    consensus, no central database to run. [How sync works →](/protocol/sync/)
  </Card>
  <Card title="Groups decide who sees what" icon="approve-check">
    Shared state is encrypted under group keys, and membership and
    capabilities are part of the operation log. [Encryption →](/protocol/encryption/)
  </Card>
  <Card title="Don't trust us. Verify us." icon="seti:lock">
    Nodes can run sealed in Intel TDX confidential VMs that attest their image
    before they get keys. [TEE attestation →](/protocol/tee-attestation/)
  </Card>
</CardGrid>
